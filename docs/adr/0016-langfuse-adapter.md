# ADR-0016: Langfuse 어댑터 — 프롬프트 조회와 트레이스 전송 설정

- 상태: 승인
- 날짜: 2026-11-22
- 관련: ADR-0001, ADR-0006, ADR-0013, ADR-0015, I-06, I-07, I-13, I-16

## 배경
런타임은 작업마다 Langfuse 에서 프롬프트를 가져온다(ADR-0006). 그리고 실행 트레이스를 Langfuse 로 보낸다(ADR-0001).

Langfuse 프로젝트는 **일본 리전**(`https://jp.cloud.langfuse.com`)에 있다. 리전마다 계정과 데이터가 분리되어 있으므로 주소는 설정으로 둔다.

확인한 사실은 다음과 같다(Langfuse 공식 문서, 2026-11-22).
- **프롬프트 조회**: `GET /api/public/v2/prompts/{name}?label=…|version=…`. 인증은 Basic(공개 키:비밀 키)이다. 폴더가 있는 이름은 URL 인코딩한다.
- **OTLP 수신**: `/api/public/otel`. OTLP/HTTP(JSON, protobuf)를 받고 gRPC 는 받지 않는다. 헤더는 `Authorization=Basic …` 와 `x-langfuse-ingestion-version=4` 다. 두 번째 헤더가 없으면 반영이 최대 10분 늦어진다.
- **프롬프트 연결 속성**: 스팬에 `langfuse.observation.prompt.name`, `langfuse.observation.prompt.version` 을 붙이면 프롬프트 버전과 연결된다.

## 검토한 대안
- **Langfuse Python SDK 로 프롬프트 조회**: 캐시와 재시도가 들어 있다. 그러나 전역 OTel 설정과 백그라운드 작업을 함께 가져온다. 또 SDK 의 대체 프롬프트(fallback) 기능은 I-13 과 충돌하므로 끄고 써야 한다. → 프롬프트 조회에는 쓰지 않는다. 트레이스 쪽 SDK 사용 여부는 엔진 PR 에서 다시 판단한다.

## 결정

### 1. 프롬프트 조회 (`LangfusePromptStore`)
- REST API 를 `httpx` 로 직접 호출한다.
- **text 프롬프트만** 쓴다. `config.model` 이 반드시 있어야 하고, 나머지 config 키는 생성 파라미터로 엔진에 전달한다.
- 캐시를 둔다.
  - **60초 동안**은 Langfuse 에 묻지 않고 캐시한 사본을 쓴다.
  - Langfuse 에 **연결할 수 없을 때만**, 최대 **1시간** 된 사본을 쓴다. 1시간이 지나면 실행을 거부한다.
  - 이 사본은 실제로 Langfuse 에서 받았던 프롬프트이므로, "임의의 기본 프롬프트로 대체하지 않는다"(I-13)에 어긋나지 않는다.
- 실패 분류(ADR-0015)는 다음과 같다.
  - 재시도함(`PromptUnavailableError`): 연결 실패, 5xx 응답.
  - 재시도하지 않음(`PromptInvalidError`): 프롬프트가 없음(404), 키가 거부됨(401/403), chat 형식, `model` 없음, 응답 형식 오류.
- 실패 사유에는 키나 프롬프트 본문을 넣지 않는다.

### 2. 트레이스 전송 설정 (`OtlpExport`)
- Langfuse 연결 정보로 표준 `OTEL_EXPORTER_OTLP_*` 환경변수를 만든다. 형식은 http/protobuf 다.
- 이 값에는 비밀 키가 들어 있다. 트레이스를 내보내는 하위 프로세스의 환경에만 넘기고, 로그나 트레이스에는 남기지 않는다(I-07).
- 스팬을 프롬프트 버전과 세션에 연결하는 방법은 Claude 엔진 PR 에서 실제 SDK 로 확인한 뒤 정한다.
  - 후보 1: Claude Code 의 자체 OTel 내보내기.
  - 후보 2: 런타임 프로세스에서 스팬 만들기.
- 연결에 쓸 속성 이름은 이 패키지의 상수로 둔다.

### 3. 키 전달
- Langfuse 키는 런타임이 시작할 때 core 의 비밀값 API 에서 받는다(ADR-0013).

## 근거
- 프롬프트 조회는 HTTP 요청 하나라서 직접 구현하는 편이 동작과 실패 처리를 정확히 통제할 수 있다.
- 짧은 캐시는 작업마다 생기는 지연을 줄인다. 오래된 사본의 사용 기한을 1시간으로 둔 것은, Langfuse 의 짧은 장애가 대화를 멈추게 하지 않으면서도 오래된 프롬프트가 무기한 쓰이지 않게 하기 위해서다.

## 결과
- `production` 라벨을 옮기면 최대 60초 뒤부터 새 버전이 쓰인다.
- Langfuse 가 1시간 넘게 장애이면, 그 사이 새로 시작한 런타임이나 캐시가 만료된 프롬프트는 실행을 거부한다.
- chat 형식 프롬프트를 쓰려면 이 어댑터와 엔진 포트를 바꿔야 한다.

## 재검토 조건
- chat 형식이나 프롬프트 합성(의존성)이 필요해질 때.
- 프롬프트 반영 지연(60초)이 문제가 될 때.
