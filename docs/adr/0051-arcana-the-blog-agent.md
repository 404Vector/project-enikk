# ADR-0051: 블로그와 노트를 맡는 에이전트 아르카나

- 상태: 승인 (§1~§3 구현. §4 승인 아래의 발행·내리기·삭제·이동은 뒤따르는 PR 에서 이 문서에 더한다)
- 날짜: 2026-11-28
- 관련: ADR-0045, ADR-0047, ADR-0049(§2 를 보탬), ADR-0050, I-35

## 배경
소유자는 블로그(볼트의 공개 노트, ADR-0049)와 볼트의 비공개 노트를 함께 관리하는 에이전트를 원한다(2026-11-27, 스레드 94bec15f). 소유자의 결정은 다음과 같다.
- 공개된 글, 초안, `Private/` 의 노트를 모두 다룬다.
- 발행·내리기는 소유자의 승인 아래에 한다. 삭제·이동도 맡기되 같은 승인 아래에 한다.
- 캐릭터는 니케 아르카나(엘리시온, 금서 도서관 관리자)다. 리타처럼 전용 채널을 쓴다.

## 검토한 대안
- **A. 에닉에게 모두 맡긴다**: 에이전트가 늘지 않는다 / 에닉의 범위가 계속 넓어지고, 비공개 노트 쓰기 권한이 모든 대화에 열린다. → 기각.
- **B. 전용 에이전트를 두고, 비공개 노트 쓰기는 그 에이전트 정의에만 준다**: 권한이 정의 하나에 묶이고, 리타와 같은 채널·위임 구조를 그대로 쓴다. → 채택.

## 결정
### 1. 에이전트 정의
- `agents/arcana.yaml`. 프롬프트 `arcana`(Langfuse). 기본 도구와 플랫폼 기본 도구(기억, 볼트 도구, 스레드 도구)를 쓴다. 이미지·Unity·스케줄러 도구는 없다.
- 새 플랫폼 권한 `vault-private` 를 아르카나 정의에만 준다.
- 에닉의 `delegates` 에 `arcana` 를 더한다(ADR-0047).
- 전용 채널 `C0CMDCK8UNR`, 표시 이름 `아르카나`, 아이콘 `:arcana:`(ADR-0045).

### 2. 비공개 노트 쓰기 (`vault-private`)
- `write_note`·`write_notes` 는 `vault-private` 를 받은 역할에게만 소유자의 비공개 노트 쓰기를 허락한다.
- 비공개 노트: `vault/` 아래 `.md` 로, 경로 중 한 폴더가 블로그가 빼는 폴더(`Private`·`private`·`templates`)이고, 에닉의 폴더(`vault/Private/enikk/`) 밖이며, 숨김·상대 경로 조각이 없는 것.
- 비공개 노트는 공개되지 않으므로 `draft` 표시를 요구하지 않는다. 커밋은 `notes: created|updated <이름>` 이고 CI 를 건너뛴다.
- 그 밖의 확인(소유자가 Slack 에서 시작한 작업, 비밀값)은 ADR-0049 §2 와 같다.
- 에닉의 기억과 자료는 이 권한으로 쓰지 못한다. 기억 도구와 ADR-0050 의 자료 쓰기로만 쓴다.

### 3. 공개 노트
- 공개 노트의 규칙은 ADR-0049 그대로다. 새 노트는 초안이고, 쓰기는 공개 여부를 바꾸지 못한다.

### 4. 승인 아래의 일 (뒤따르는 PR)
- 발행·내리기·삭제·이동을 요청하면 승인 채널에 버튼이 올라가고, 소유자가 누른 뒤 core 가 실행한다. 설계는 그 PR 에서 이 절에 적는다.

## 근거
- 비공개 노트는 블로그 공개와 상관없으므로 `draft` 를 지킬 필요가 없다. 위험은 다른 대화가 소유자의 개인 노트를 고치는 것이라, 권한을 에이전트 정의 하나에 묶었다.
- 에닉의 폴더를 빼서, 기억의 쓰기 경로(ADR-0028)와 자료의 쓰기 경로(ADR-0050)가 섞이지 않게 했다.

## 결과
- I-35 가 바뀐다: 에닉의 폴더 밖 비공개 노트는 `vault-private` 를 받은 역할만 쓴다.
- `arcana` 프롬프트가 production 으로 승격되기 전에는 아르카나 채널의 요청과 위임이 실패한다(ADR-0045 와 같다).
- git 이력이 볼트의 되돌리기 수단이다.

## 재검토 조건
- 다른 역할에도 비공개 노트 쓰기가 필요해질 때.
- 비공개 노트에도 공개 여부 확인이 필요한 경로(예: 블로그 설정 변경)가 생길 때.
