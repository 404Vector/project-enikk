# ADR-0027: 스레드의 에이전트는 그 스레드에 올라온 다른 글도 본다

- 상태: 승인
- 날짜: 2026-11-22
- 관련: ADR-0003, ADR-0022, ADR-0025, I-11, I-12

## 배경
Slack 스레드 하나는 에이전트 하나(assistant 등)에 묶이고, 그 에이전트의 대화 이력이 곧 스레드의 세션이다(I-11). 그런데 같은 스레드에는 다른 글도 올라온다.

- 위임받은 개발 에이전트의 답(ADR-0022)
- core 가 올리는 PR 진행 알림(ADR-0025)

이 글들은 소유자에게는 보이지만, 스레드의 에이전트 대화에는 들어가지 않는다. 2026-11-22 에 개발 에이전트가 스레드에 ADR 초안을 남겼고, 소유자는 "방금 초안대로 만들어 줘" 라고 했다. 그러나 assistant 는 초안을 본 적이 없어 작업을 넘기지 못했다.

## 검토한 대안
- **위임 결과를 assistant 대화에 바로 이어 붙임**: 엔진 대화 이력을 core 가 고쳐 써야 한다. 엔진마다 형식이 다르다. → 기각.
- **다음 차례의 입력 앞에 붙임**: 소유자가 다음 말을 할 때, 그 사이 스레드에 올라온 다른 글을 입력 앞에 붙인다. 엔진과 무관하다. → 채택.
- **장기 기억(메모리)으로 해결**: 스레드를 넘어 쌓이는 기억은 따로 필요하다. 그러나 이번 문제는 "같은 스레드에 보이는 것을 모른다" 는 것이라 메모리와 별개다. 메모리는 다른 ADR 에서 정한다.

## 결정
- core 가 스레드의 에이전트에게 새 작업을 만들 때, 그 세션의 직전 작업 이후 **그 스레드에 다른 세션의 작업으로 올라간 글**(위임 결과, core 알림)을 입력 앞에 붙인다.
  - 머리말 `[이 스레드에 그 사이 다른 에이전트와 시스템이 올린 내용]`, 글마다 시각, 그리고 `[소유자의 새 메시지]` 뒤에 소유자의 말.
  - 자기 답은 이미 자기 대화에 있으므로 넣지 않는다.
  - 최근 20개까지, 글 하나는 4,000자까지. 입력 한도(40,000자)를 넘으면 오래된 글부터 뺀다. 소유자의 말은 자르지 않는다.
- 이미 그 스레드에 게시된 글만 넣는다. 다른 스레드의 글이나 다른 세션의 대화 이력은 넣지 않는다.

## 근거
- 스레드에 보이는 것과 스레드 에이전트가 아는 것을 일치시킨다. 소유자 입장에서 스레드가 곧 대화다.
- 새로 드러나는 정보가 없다. 이미 같은 스레드에 공개된 글이다.

## 결과
- I-12 를 고친다: 대화 이력은 엔진 사이에 옮기지 않지만, 같은 스레드에 이미 게시된 글은 그 스레드 에이전트의 다음 입력에 넣는다.
- 작업 입력이 길어질 수 있다. 위의 한도로 묶는다.

## 재검토 조건
- 스레드 밖에서도 공유돼야 하는 기억이 필요해질 때 → 메모리 ADR.
