# ADR-0026: Slack 알림을 어디에 올리는가 — 배포 알림은 #release, 개발 요청은 상태와 상세를 나눈다

- 상태: 승인
- 날짜: 2026-11-22
- 관련: ADR-0018, ADR-0020, ADR-0022, ADR-0023, ADR-0025, ADR-0036, I-01, I-11

## 배경
지금까지 Slack 알림의 위치는 다음과 같았다.

- 배포 성공·실패, 이미지 빌드 실패, 롤백 결과는 소유자 DM 으로 간다(ADR-0020 §3, ADR-0023 §1·§4·§6). 배포·빌드 실패에는 [되돌리기] 버튼이 붙고 소유자만 누를 수 있다.
- 개발 에이전트에 위임한 요청은 원래 요청 스레드에 결과를 올린다(ADR-0022 §2, ADR-0025 §2). 개발 에이전트의 답 전문(바뀐 파일, 검사 결과 등)이 그대로 원래 스레드에 올라갔다.

소유자는 다음을 원한다(2026-11-22, Slack 요청).

- 배포 관련 알림은 DM 이 아니라 #release 채널(`C0CKT1ZNZ43`)에서 본다. 봇은 이미 그 채널에 초대되어 있다.
- 원래 요청 스레드에는 상태와 링크만 둔다. PR 본문, diff, 파일 목록 같은 상세는 소유자 DM 의 PR 검토 스레드에만 둔다. 두 스레드는 서로 링크로 이어진다.

두 번째 항목은 PR #43 에서 이미 구현했다. 이 ADR 은 두 가지를 "Slack 알림을 어디에 올리는가"라는 하나의 결정으로 함께 기록한다.

## 검토한 대안
- **배포 알림을 DM 에 그대로 둠**: 바꿀 것이 없다. 그러나 소유자가 원하는 곳이 아니다. → 기각.
- **배포 알림을 채널로 옮기고 [되돌리기] 는 DM 에만 둠**: 채널에 버튼이 노출되지 않는다. 그러나 알림과 조치가 두 곳으로 갈라지고, 소유자는 채널에서 바로 되돌리기를 원한다. → 기각.
- **배포 알림과 [되돌리기] 를 모두 채널에 두고, 누른 사람을 서버에서 확인**: 채택. 버튼 처리는 이미 누른 사람이 소유자인지 확인하므로(ADR-0020 §2, I-01), 채널에서도 같은 확인이 권한을 지킨다.
- **채널 게시가 실패하면 알림을 버림**: 배포 실패를 놓치면 되돌리기가 늦어진다. → 기각. DM 으로 대신 보낸다.

## 결정

### 1. 배포 관련 알림은 설정 채널로 보낸다
- 배포 성공·실패, 이미지 빌드 실패, 롤백 결과(`DeploymentFinished`, `BuildFailed`) 알림은 Slack 커넥터가 설정 채널에 올린다.
- 채널 ID 는 코드에 박지 않는다. `config/slack.yaml` 의 `deploy_notify_channel` 이고, 환경변수 `ENIKK_CONNECTOR_DEPLOY_NOTIFY_CHANNEL` 로 덮어쓸 수 있다(P-05). 기본값은 `C0CKT1ZNZ43`(#release)이다.
- 봇이 그 채널의 구성원이어야 한다.
- core 는 바뀌지 않는다. core 는 지금처럼 알림을 `notices` 큐에 넣고, 어디에 올릴지는 커넥터가 정한다.
- 승인 요청, 검사 실패, 승인 결과(ADR-0020)는 계속 소유자 DM 으로 간다. (ADR-0036 으로 대체: 승인 채널로 가고, 실패하면 소유자 DM 으로 간다.)

### 2. [되돌리기] 는 채널에서도 소유자만 실행한다
- 채널의 배포 실패·빌드 실패 알림에도 [되돌리기] 버튼을 둔다(롤백 결과에는 지금처럼 두지 않는다).
- 채널에서는 누구나 버튼을 볼 수 있다. 커넥터는 버튼을 처리할 때 누른 사람의 user id 가 `config/slack.yaml` 의 `owner` 인지 확인한다(기존 확인 로직 그대로, I-01).
- 소유자가 아니면 core 를 호출하지 않고 메시지도 바꾸지 않는다. 그 사람에게만 보이는 메시지(`chat.postEphemeral`)로 권한이 없다고 알린다. 이 안내는 정해진 문구이며, 아무 작업도 만들지 않는다.

### 3. 채널에 올리지 못하면 소유자 DM 으로 보낸다
- 채널 게시가 어떤 이유로든 실패하면(`not_in_channel`, `channel_not_found`, 권한 오류, 네트워크 오류 등) 오류를 로그로 남기고 같은 알림을 소유자 DM 으로 보낸다. 맨 위에 "채널에 올리지 못해 DM 으로 보냅니다" 한 줄을 붙인다.
- DM 으로 보낸 알림의 [되돌리기] 도 같은 소유자 확인을 거친다.
- DM 게시마저 일시적 오류로 실패하면 알림을 확인 처리하지 않는다. 그래서 다음 조회에서 채널부터 다시 시도한다(at-least-once, ADR-0018 의 outbox 와 같은 방식).

### 4. 개발 요청의 알림: 원래 요청 스레드에는 상태와 링크, 상세는 DM 검토 스레드 (PR #43)
> 이 절은 ADR-0036 이 대체한다(부분 대체). PR 검토 스레드는 소유자 DM 이 아니라 승인 채널의 승인 메시지 스레드이고, 원래 요청 스레드에는 상태마다 새 글 대신 PR 상태 카드 하나를 두어 `chat.update` 로 고친다. 검토 스레드 링크는 별도 글이 아니라 카드에 있다. 위임 결과 한 줄(PR 링크), 개발 역할 보고 전문의 위치, 양방향 링크는 그대로 유효하다.

- **원래 요청 스레드**(채널 또는 DM): 상태만 올린다. 위임 접수, 작업 결과 한 줄(PR 링크), 검사 통과·승인 요청 / 검사 실패, PR 검토 스레드 링크, 머지·반려·닫힘, 배포 성공·실패 한 줄(ADR-0025 §2).
  - 개발 에이전트의 답에 PR 링크가 있으면 core 가 답 대신 상태 한 줄을 올린다. PR 링크가 없는 답(PR 을 만들지 않은 이유, 되묻는 질문)은 보여 줄 다른 곳이 없으므로 그대로 올린다.
- **PR 검토 스레드**(소유자 DM 의 승인 요청 또는 검사 실패 메시지의 스레드): 원래 요청 스레드 링크, PR 상세(본문, 바뀐 파일, 검사 결과), 개발 에이전트의 보고 전문, diff 파일.
- **양방향 링크**: 커넥터가 DM 을 올린 뒤 그 permalink(`chat.getPermalink`)와 PR 브랜치를 core(`POST /v1/review-threads`)에 알린다. core 는 브랜치(`agent/<세션 ID>`)로 위임 세션의 `reply_to` 를 찾아 원래 스레드에 검토 스레드 링크를 올리고(outbox), 원래 스레드 위치와 보고를 돌려준다. 커넥터는 원래 스레드의 permalink 를 DM 스레드 첫 댓글로 올린다.
- permalink 를 얻지 못하거나 core 호출이 실패하면 링크 없이 나머지를 계속 올린다.
- 배포 알림 채널(§1)에는 상세 링크를 넣지 않는다. 배포 알림은 지금처럼 PR 링크와 앱별 결과를 담는다.

### 대체 범위
- **ADR-0020 §3** 의 "core 는 결과를 소유자 DM 으로 알린다"와 "실패하면 DM 에 [되돌리기] 버튼을 붙인다" 중 *알림 위치* 부분을 대체한다. 승인 흐름(§1·§2·§4)과 배포 실패 대응의 나머지(RollingUpdate, 스모크 검사, 되돌리기 PR)는 그대로 유효하다.
- **ADR-0023** 의 배경과 §1·§4·§5·§6 에서 배포·빌드·롤백 알림을 *DM* 으로 보낸다고 한 부분을 대체한다. 배포 감시, 판정, 묶음, 스모크 검사, 되돌리기 PR 생성, 롤백 판정, DB 스키마 규칙은 그대로 유효하다.
- 두 ADR 모두 부분 대체이므로 상태는 `승인` 으로 두고, 해당 위치에 이 ADR 로 대체됐다는 표시를 단다(ADR-0024 가 ADR-0020 을 부분 대체할 때와 같은 방식).

## 근거
- 버튼 처리에서 누른 사람을 확인하는 것은 커넥터가 Slack 이 보낸 `user.id` 로 한다. Socket Mode 로 받은 상호작용이라 Slack 앱 토큰 없이 위조할 수 없다(ADR-0018). 채널이든 DM 이든 같은 코드가 확인한다.
- `chat.postEphemeral` 은 `chat:write` 스코프로 호출할 수 있다고 알고 있다. `chat.getPermalink` 는 별도 스코프가 필요 없다고 알고 있다. 이 ADR 을 쓰면서 Slack 문서를 다시 열어 보지는 않았다. 반영 뒤 실제 호출로 확인한다.
- 채널 ID 를 설정으로 두면 채널을 바꿔도 코드를 고치지 않는다(P-05).

## 결과
- #release 의 다른 구성원도 배포 결과, 커밋, PR 제목, 실패한 앱과 이유를 볼 수 있다. 저장소가 공개이므로 새로 드러나는 정보는 없다고 본다.
- 소유자가 아닌 사람이 [되돌리기] 를 누르면 그 사람에게만 거절 안내가 간다. I-01 에 이 예외를 적는다.
- 봇이 채널에서 빠지면 알림은 DM 으로 오고, 로그에 오류가 남는다.

## 재검토 조건
- 채널에 여러 사람이 있어 [되돌리기] 버튼의 노출이 문제가 될 때 → 버튼을 DM 에만 두는 대안.
- 배포 알림을 받는 사람이 늘어 소유자 외의 사람도 되돌리기를 해야 할 때 → I-01 과 함께 재검토.
