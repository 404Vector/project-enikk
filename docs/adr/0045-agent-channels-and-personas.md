# ADR-0045: 에이전트 전용 채널과 표시 이름·아이콘

- 상태: 승인
- 날짜: 2026-11-26
- 관련: ADR-0005, ADR-0018, ADR-0036, ADR-0041, ADR-0043, ADR-0044, I-01, I-15

> 결정은 2026-11-25~26 소유자가 Slack 스레드에서 확정했다(앱 하나, 소유자가 채널 개설, 에닉은 DM 유지, 공개 채널, 첫 에이전트 리타).

## 배경

- 소유자는 에이전트를 늘려 도구를 나눌 계획이다(ADR-0041). 첫 에이전트는 게임 제작 담당 '리타'다. 리타에게는 이미지 생성(ADR-0043)과 Unity 에디터(ADR-0044) 도구를 준다.
- 소유자는 에이전트마다 자기 Slack 창구를 두기를 원했다. 처음 낸 안은 에이전트마다 Slack 앱을 하나씩 만드는 것이었다.
- 제약:
  - 워크스페이스는 무료 플랜이다. 앱은 10개까지만 설치된다.
  - 앱은 `apps.manifest.create` 로 만들 수 있다. 그러나 설치(OAuth 승인)와 Socket Mode 의 앱 수준 토큰 발급은 사람이 해야 한다.
  - 앱 설정 토큰은 사용자에게 묶여 있고 12시간마다 갱신해야 한다(확인 2026-11-25, <https://docs.slack.dev/reference/methods/apps.manifest.create>, <https://slack.com/help/articles/115002422943>).

## 검토한 대안

- **에이전트마다 앱**: 이름·아이콘·멘션·DM 이 따로 생긴다 / 10개 한도에 걸린다. 에이전트마다 수작업 설치와 비밀값 두 개가 늘고, 앱 설정 토큰을 계속 보관해야 한다.
- **앱 하나 + 채널마다 에이전트 + 표시 이름·아이콘** (선택): 비밀값과 설치가 늘지 않는다 / 에이전트를 따로 멘션하거나 DM 할 수 없다.

## 결정

1. **앱은 하나다.** 에이전트의 글은 `chat:write.customize` 로 그 에이전트의 이름과 아이콘(워크스페이스 커스텀 이모지)을 붙여 보낸다.
2. **전용 채널**: `config/slack.yaml` 의 `agent_channels` 가 채널 하나를 에이전트 하나에 묶는다. 에이전트 정의는 Slack 을 모른다(I-15).
   - 그 채널에서 소유자가 쓴 최상위 글은 멘션이 있든 없든 그 에이전트와의 새 대화가 된다. 같은 글의 `app_mention` 이벤트는 버린다.
   - 스레드 답글은 그 스레드에 대화가 있을 때만 이어진다.
   - 소유자 외의 글은 무시한다(I-01).
3. **표시 이름과 아이콘은 채널이 정한다.** connector 는 에이전트 채널에 보내는 답, 실패 안내, 예약 메시지, 처리 중의 [취소] 버튼, 파일과 파일 실패 안내에 그 채널의 이름과 아이콘을 붙인다(버튼은 2026-11-26 추가: 처리 중에 앱 이름이 보이지 않게. 파일은 2026-11-27 추가: 리타가 올린 파일이 에닉으로 보이지 않게).
   - 파일은 `files.completeUploadExternal` 의 `username`·`icon_emoji` 로 붙인다(같은 `chat:write.customize` 범위, 확인 2026-11-27, <https://docs.slack.dev/reference/methods/files.completeUploadExternal>). slack-sdk 의 `files_upload_v2` 가 남은 인자를 그 단계로 넘긴다.
   - 승인 요청과 배포 알림은 앱 이름 그대로 나간다.
   - outbox 계약은 바꾸지 않는다. 한 채널의 대화는 모두 그 채널의 에이전트이기 때문이다.
4. **채널은 소유자가 만든다.** 공개 채널을 만들고 봇을 초대한 뒤 그 ID 를 `agent_channels` 에 넣는다. 에닉에게 채널을 만드는 권한은 주지 않는다.
   - 에이전트 채널은 배포 알림 채널이나 승인 채널과 같을 수 없다. 한 채널은 한 번만 쓴다.
5. **에닉은 예외다.** 에닉은 지금처럼 DM 과 멘션으로 대화한다. 알림이 실패하면 DM 으로 보내는 경로도 그대로다.
6. **직접 대화 (ADR-0041 §2 보완)**:
   - ADR-0041 §2 는 "대화 맥락은 에닉만 갖는다"고 정했다. 이 결정으로 에이전트 채널의 에이전트도 그 채널에서 소유자와 직접 대화한다.
   - 에닉이 다른 에이전트를 부르는 A2A 는 이 결정에 포함하지 않는다. A2A 는 필요할 때 ADR-0041 §2 대로 따로 만든다.
7. **리타** (`agents/rita.yaml`):
   - 도구: 이미지 생성과 Unity 전체, 기본 도구.
   - 주지 않는 것: 스케줄러, 프롬프트 후보, GitHub 토큰. enikk 자체를 바꾸는 일은 에닉이 한다.
   - 기억 등 기본 플랫폼 도구는 다른 역할과 같이 받는다.
   - 프롬프트는 Langfuse 의 `rita` 다. 정의가 머지된 뒤 후보를 만들고 소유자가 승격한다.

## 근거

- 무료 플랜 한도와 수작업 설치를 피하면서도, 소유자가 채널을 보고 에이전트를 구분할 수 있다.
- 표시를 채널에서 정하면 core 와 계약을 바꾸지 않고 connector 와 설정만 바꾸면 된다.
- `chat:write.customize` 는 앱이 이름과 아바타를 바꿔 글을 보내게 하는 봇 범위다. `chat:write` 와 함께 요청해야 한다. 쓰는 법은 `chat.postMessage` 의 authorship 절(`username`, `icon_emoji`)을 따른다(확인 2026-11-26, <https://docs.slack.dev/reference/scopes/chat.write.customize>).

## 결과

- 매니페스트에 `chat:write.customize` 를 더했다. 소유자가 앱 설정에 반영하고 다시 설치해야 이름과 아이콘이 붙는다. 그 전의 동작(인자를 무시할지 거부할지)은 확인하지 못했다.
- `rita` 프롬프트가 production 으로 승격되기 전에는 리타 채널의 요청이 실패한다.
- 리타도 실행 칸과 runtime 메모리를 에닉과 나눠 쓴다.
- 에이전트를 더할 때는 정의 파일, `agent_channels` 항목, 프롬프트 후보를 함께 낸다.

## 재검토 조건

- 에이전트마다 따로 멘션하거나 DM 해야 할 때(앱 분리를 다시 본다).
- 유료 플랜으로 바꿔 앱 한도가 없어질 때.
- 한 채널에서 여러 에이전트가 대화해야 할 때(표시를 outbox 계약으로 옮긴다).
