# ADR-0004: agentgateway 를 MCP 통로에만 배치

- 상태: 승인
- 날짜: 2026-11-21
- 관련: ADR-0002, ADR-0003, I-03, I-05, I-09

## 배경
에이전트는 밖으로 두 종류의 요청을 보낸다.
1. **모델 호출**: Anthropic(구독 토큰), Gemini
2. **도구 호출**: 여러 MCP 서버

agentgateway 는 이 통로들에 끼울 수 있는 프록시다(에이전트를 실행하는 곳이 아니다).
MCP 서버를 여러 개 연결할 예정이므로 MCP 통합 지점이 필요하다.

## 검토한 대안
- **A. MCP 통로에만 배치**: 모델 호출은 직접. 구독 토큰이 게이트웨이를 지나가지 않는다.
- **B. 모델 통로 + MCP 통로 모두 배치**: 모델 트래픽까지 한 곳에서 관측. 단, 구독 토큰이 게이트웨이를 통과하므로 인증 헤더(`Authorization`, `anthropic-beta`)의 무손실 전달을 보장해야 한다.
- **LiteLLM**: LLM 라우팅·예산 관리 중심. 구독 토큰 + 모델 직접 호출 구조에서는 장점이 약하다.

## 결정
**agentgateway 를 MCP 통로에만 배치한다 (A안).**

## 근거
- Claude 모델 호출이 일반 Claude Code 사용과 동일한 경로가 되어 ADR-0002 의 정책상 회색지대가 줄어든다.
- 모델 트레이싱은 엔진(Agent SDK 등)의 OpenTelemetry 계측으로 얻으므로 게이트웨이를 거치지 않아도 잃는 것이 없다.
- Claude Code LLM 게이트웨이 문서(2026-11-21 확인, https://code.claude.com/docs/en/llm-gateway.md): 구독 로그인 상태로 게이트웨이를 거칠 경우 게이트웨이가 `Authorization` 과 `anthropic-beta` 헤더를 그대로 전달해야 하며, 제거 시 401 이 발생한다. → B안은 추가 검증 부담이 있다.

## 결과
- 에이전트는 개별 MCP 서버 주소를 모르고 agentgateway 엔드포인트 하나만 안다 (I-05).
- MCP 서버의 외부 자격증명(예: 외부 API 키)은 해당 MCP 서버만 가진다 (I-09).
- Gemini 모델 호출(구독 토큰이 아닌 경우)은 추후 필요 시 게이트웨이 경유를 별도로 검토할 수 있다.

## 재검토 조건
- 모델 트래픽의 중앙 통제(속도 제한, 감사)가 필요해질 때 → B안 검토 (새 ADR).
