# ADR-0045: 이미지 하루 상한을 추정 비용으로 하고, 값은 Langfuse 도구 설정에 둔다

- 상태: 승인
- 날짜: 2026-11-26
- 관련: ADR-0032, ADR-0037, ADR-0043, I-36

> 결정은 2026-11-26 소유자가 Slack 스레드에서 확정했다(하루 $1, 장수 상한 없음, 추정 단가, 값은 커밋 없이 바꿈, Langfuse 프롬프트 config 안 채택, 누적은 메모리).

## 배경

- ADR-0043 §2 의 하루 상한은 장수(100장)였다. 장당 값은 모델과 해상도에 따라 $0.045~$0.24 로 5배 넘게 차이가 나서, 장수로는 소유자가 신경 쓰는 돈을 막지 못한다.
- 소유자는 상한 값을 커밋 없이 바꾸기를 원했다. 차트 값은 바꿀 때마다 PR 이 필요하다.
- 값을 에닉이 스스로 바꿀 수 있으면 상한이 의미가 없다. 소유자만 바꿀 수 있어야 한다.
- Gemini API 키에는 Google 쪽 결제 한도가 따로 걸려 있어, 상한을 조금 넘는 것은 감수할 수 있다(소유자, 2026-11-26).

## 검토한 대안

- **사용액을 Langfuse 트레이스에서 읽어 막음**: 기록은 이미 있다. 그러나 트레이스는 비동기로 늦게 쌓여 연달아 부르면 넘치고, Langfuse 가 멈추면 판단할 수 없다. → 기각. 트레이스는 보는 용도로만 둔다.
- **core DB 에 설정 테이블**: 값을 바꾸는 경로를 새로 만들어야 하고, 에닉의 도구로 열면 에닉이 스스로 예산을 올릴 수 있어 소유자 승인 절차까지 새로 필요하다. → 기각.
- **Langfuse 프롬프트 `config-imagegen` 의 config**: 버전이 남고, 화풍(ADR-0043 §3)·스킬과 같은 후보·승격 절차(ADR-0032)를 그대로 써서 소유자만 바꾼다. 서버는 이미 Langfuse 를 읽는다. → 채택.
- 누적 위치: core DB(재시작에도 정확, 마이그레이션·API 추가) / **메모리**(재시작·배포 때 0 으로). 상한이 작고 넘침을 감수하므로 메모리. → 메모리 채택.

## 결정

### 1. 하루 예산 (ADR-0043 §2 의 장수 상한을 대체)
- `imagegen` 은 장수를 세지 않고, 오늘(Asia/Seoul) 쓴 추정 비용을 센다. 이번 이미지의 추정 비용을 더해 예산을 넘으면 거부한다. 0 이면 생성을 멈춘다.
- 추정 비용은 설정의 가격표(모델 × 해상도)다. 가격표에 없는 조합은 예산을 지킬 수 없으므로 거부한다.
- Gemini 호출이 실패하면 그 비용을 돌려준다. 누적은 메모리에만 있어 서버가 다시 뜨면 0 부터 센다.
- 응답에 장당 추정 비용, 오늘 누적, 오늘 예산을 적는다.

### 2. 도구 설정 `config-*`
- 새 프롬프트 종류 "도구 설정": 이름이 `config-` 로 시작하는 Langfuse 텍스트 프롬프트. 본문은 사람을 위한 메모이고, 값은 config 에 둔다. 이름마다 계약이 있고(`enikk_contracts.tool_configs`), 목록에 없는 이름과 계약에 맞지 않는 값은 거부한다. `model` 은 필요 없다.
- 지금 있는 설정은 `config-imagegen` 하나다: `daily_budget_usd`(0~100).
- 후보는 `propose_prompt` 의 `config.values` 로 만든다. 도구 설정에는 `model`·`effort`·`description`·`requires` 를 쓸 수 없고, 다른 프롬프트에는 `values` 를 쓸 수 없다. 승격 카드에 "(도구 설정)" 으로 표시된다. production 은 소유자의 승격으로만 바뀐다(I-36).
- `imagegen` 은 production 만 읽고 60초 동안 캐시한다. Langfuse 에 닿지 못하면 1시간 안의 캐시를 쓰고, 그것도 없으면 생성을 거부한다. 값이 계약에 맞지 않아도 거부한다.
- production 버전이 아직 없으면 차트 값 `defaultBudgetUsd`(기본 1)를 쓴다. Langfuse 연결 없이(`tracing: false`) 돌 때도 이 값을 쓴다.

## 근거

- 가격표는 ADR-0043 의 근거와 같다(2026-11-25 확인). 기본 모델 1K 기준 $1 은 14장이다.
- 화풍이 이미 Langfuse 의 후보·승격으로 운영되고 있어 새 승인 경로가 생기지 않는다.

## 결과

- 소유자가 예산을 바꾸려면 에닉에게 `config-imagegen` 후보를 요청하고 승격한다. 커밋은 필요 없다. 반영은 최대 60초 뒤다.
- 재시작·배포가 잦은 날에는 하루 예산을 몇 번 더 쓸 수 있다. Google 쪽 결제 한도가 최종 방어선이다.
- 실제 청구는 토큰 단위라 참조 이미지가 많으면 추정보다 비쌀 수 있다.
- 차트 값 `dailyLimit` 과 설정 `daily_limit` 은 없어졌다.

## 재검토 조건

- 예산을 재시작 너머로 정확히 지켜야 할 때(core 에 누적).
- 추정 비용과 실제 청구가 크게 어긋날 때(응답의 토큰 수로 정산).
- 도구 설정이 여러 개로 늘어 계약 목록 관리가 번거로워질 때.
