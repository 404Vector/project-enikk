# ADR-0009: Slack 봇과 에이전트 런타임을 별도 프로세스로 분리

- 상태: 대체됨(ADR-0010)
- 날짜: 2026-11-21
- 관련: ADR-0007, I-01, I-22

## 배경
- Slack 은 이벤트 수신 후 3초 안에 응답(ack)을 요구한다. 에이전트 실행은 수 분이 걸릴 수 있다.
- 자기 개선 구조(ADR-0007)로 배포가 잦다. 배포·재시작이 진행 중인 대화를 끊으면 안 된다.

## 검토한 대안
- **한 프로세스**: 봇이 ack 후 같은 프로세스에서 에이전트를 백그라운드 실행. 단순하지만 재시작 시 진행 중 작업이 사라지고, 에이전트 장애가 Slack 연결까지 끊는다. → 기각.
- **분리 + 작업 큐**: 채택.

## 결정
- **Slack 봇**: Socket Mode 연결 유지, 소유자 확인(I-01), 즉시 ack, 작업을 큐에 넣는다. 에이전트를 실행하지 않는다.
- **에이전트 런타임**: 큐에서 작업을 꺼내 실행하고, 결과를 Slack API 로 해당 스레드에 게시한다.
- 둘은 큐를 통해서만 통신한다 (I-22).

## 결과
- 봇과 런타임을 독립적으로 재시작·배포할 수 있다.
- 작업이 큐에 남으므로 런타임 재시작 후 재시도할 수 있다. 따라서 작업 처리는 재시도해도 안전해야 한다(중복 게시 방지).
- 큐 구성요소가 하나 추가된다.

## 미결정
- 큐 기술 (Redis Streams 등).
- 작업 재시도 정책과 중복 방지 방식.
