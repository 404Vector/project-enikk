# ADR-0025: 위임한 스레드에서 PR 을 끝까지 따라가고, 같은 PR 을 이어서 고친다

- 상태: 승인 (위임한 세션을 따라가는 부분은 ADR-0037 4e 로 대체: 새 위임은 없고, 이미 있는 위임 세션의 카드만 그대로 동작)
- 날짜: 2026-11-22
- 관련: ADR-0020, ADR-0021, ADR-0022, ADR-0023, ADR-0026, ADR-0036, I-11

## 배경
소유자는 Slack 만으로 개발하기를 원한다. 지금 흐름에는 두 군데가 끊겨 있다.

- 개발 에이전트가 PR 을 만든 뒤, 요청한 스레드에는 PR 링크만 남는다. 승인 요청, 검사 실패, 머지, 배포 결과는 소유자 DM 으로만 가고 원래 스레드는 모른다(ADR-0020 §4 의 남은 일).
- 같은 스레드에서 "여기 고쳐 줘" 라고 해도 개발 작업마다 브랜치가 새로(`agent/<task>`) 생겨 PR 이 하나 더 열린다. 검사 실패를 고치거나 리뷰 의견을 반영하려면 같은 PR 에 커밋이 더해져야 한다.

개발 에이전트는 스레드마다 세션 하나를 쓴다(`<thread>:developer`, ADR-0022). 세션의 대화 이력도 core 에 이어진다(ADR-0014).

## 검토한 대안
- **PR 번호를 assistant 가 기억해 위임 요청에 넣음**: LLM 의 기억에 기대므로 틀릴 수 있다. → 기각.
- **스레드(개발 세션)마다 작업 브랜치 하나**: 같은 스레드의 개발 작업은 항상 같은 브랜치에서 일한다. 브랜치 이름에서 세션과 스레드를 찾을 수 있다. → 채택.

## 결정

### 1. 스레드마다 작업 브랜치 하나
- 개발 에이전트의 작업 브랜치는 `agent/<개발 세션 ID>` 다.
- 그 브랜치가 원격에 있으면(= 열린 PR 이 있다) 받아서 그 위에서 일하고, 새 PR 을 만들지 않고 push 만 한다. 없으면 `main` 에서 새로 만든다.
  - 머지되면 브랜치는 저장소 설정으로 지워지고, 반려되면 core 가 지운다(ADR-0020). 그래서 브랜치가 남아 있다는 것은 PR 이 열려 있다는 뜻이다.
- 개발 에이전트에게 주는 작업 설명(task brief)에 이어서 하는 작업인지 적는다. 프롬프트는 바꾸지 않는다.
- 이미 열린 PR 이 `main` 보다 뒤처졌으면 core 가 승인 요청 전에 최신으로 만든다(ADR-0020 §4).

### 2. 원래 스레드로 결과 알림
> 아래 표처럼 상태마다 새 글을 올리는 방식은 ADR-0036 이 대체한다(부분 대체): 원래 스레드에는 PR 상태 카드 하나를 두고 `chat.update` 로 고치며, 실패(검사 실패, 머지 거부, 배포·빌드 실패, 롤백)일 때만 한 줄을 더 올린다. 버튼은 승인 채널에만 있다. §1(스레드마다 작업 브랜치 하나)은 그대로 유효하다.

core 가 `agent/<세션 ID>` 브랜치의 PR 에 일어난 일을 그 세션의 원래 스레드(`reply_to`)에 짧게 올린다.

| 때 | 스레드에 올리는 말 |
|---|---|
| 검사 통과, 승인 요청을 보냄 | PR 이 준비되어 소유자에게 승인 요청을 보냈다 |
| 검사 실패 | 실패한 검사 이름, 그리고 "이 스레드에서 고쳐 달라고 하면 같은 PR 에서 고친다" |
| 머지 / 반려 / 닫힘 | 결과 |
| 그 머지 커밋의 배포 결과 | 배포 성공 또는 실패 |

- 이 알림은 소유자 DM 알림(ADR-0020, ADR-0023)과 별개로, 대화의 흐름을 잇기 위한 것이다. 버튼은 DM 에만 있다.
- 스레드 메시지는 outbox 로 보낸다(I-11). 세션의 가장 최근 작업에 붙인다.
- 예전 브랜치(`agent/<작업 ID>`)는 작업에서 세션을 찾아 같은 방식으로 알린다.

## 근거
- 브랜치 이름이 세션을 가리키면 PR 과 스레드를 잇는 데 별도 기록이 필요 없다.
- 세션 이력이 이어지므로, 개발 에이전트는 같은 스레드의 이전 작업을 기억한 채 같은 브랜치에서 이어서 고친다.

## 결과
- 같은 스레드의 개발 요청은 한 번에 하나의 PR 로 모인다. 서로 다른 변경을 동시에 진행하려면 다른 스레드에서 요청한다.
- 스레드에서 PR 의 진행을 끝까지 볼 수 있다. DM 은 결정(승인, 되돌리기)을 위한 곳으로 남는다.

## 재검토 조건
- 한 스레드에서 여러 PR 을 동시에 진행하고 싶어질 때.
