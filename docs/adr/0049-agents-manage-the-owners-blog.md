# ADR-0049: 에닉이 소유자의 블로그(볼트의 공개 노트)를 관리한다

- 상태: 승인
- 날짜: 2026-11-27
- 관련: ADR-0028(§2 를 공개 노트에 한해 부분 대체), ADR-0035, ADR-0042, I-01, I-35

## 배경
소유자는 에닉이 블로그 글을 쓰고, 이미 쓴 글도 고쳐 주기를 바란다(2026-11-27, 스레드 94bec15f). 블로그는 볼트 저장소 그 자체다(ADR-0028 배경).
- 볼트 `main` 에 push 하면 Quartz 가 렌더해 공개 블로그로 배포한다.
- 공개에서 빠지는 것은 `Private`·`private`·`templates`·`.obsidian` 폴더와 frontmatter 가 `draft: true` 인 노트뿐이다.

지금은 에닉이 `vault/Private/enikk/` 밖에 쓸 수 없고(ADR-0028 §2, I-35), 볼트를 읽을 때도 색인의 요약(`recall`)만 볼 수 있어 글 전체를 고칠 수 없다.

## 검토한 대안
- **A. 에닉이 공개 노트를 자유롭게 쓰고 공개도 정한다**: 가장 편하다 / 한 번의 잘못된 쓰기로 글이 바로 공개된다. 공개는 되돌리기 어렵다(검색·캐시). → 기각.
- **B. 에닉은 새 노트와 자기가 만든 노트만 쓴다**: 안전하다 / 소유자가 쓴 글을 관리할 수 없다. 소유자가 거절했다("내가 쓴 것도 수정할 수 있어야 한다. git 으로 히스토리가 관리된다"). → 기각.
- **C. 어떤 공개 노트든 쓰되, 공개 여부(`draft` 표시)는 바꾸지 못한다**: 소유자의 글도 고칠 수 있다. 새 글은 항상 초안으로 들어가고, 공개·비공개 전환은 소유자가 Obsidian 에서 한다. 잘못 고친 내용은 git 이력으로 되돌린다. → 채택.

## 결정
### 1. 도구
- `read_note(path)`: 볼트의 노트 하나를 frontmatter 까지 그대로 읽는다(`vault/` 아래 `.md`, `.obsidian/` 제외). 고치기 전에 원문을 읽는 데 쓴다. 읽기 전용 토큰(`watch`)을 쓴다.
- `write_note(path, text)`: 공개 노트 하나를 만들거나 통째로 바꾼다. `text` 는 frontmatter 를 포함한 파일 전체다. 기억 쓰기 토큰(`memory`)으로 contents API 를 쓴다(ADR-0028 §4 와 같은 경로).
- 두 도구는 기억 도구와 함께 플랫폼 기본 도구로 주어진다(`platform_defaults`).

### 2. core 가 쓰기 전에 확인하는 것
- 소유자가 Slack 에서 시작한 작업인지(ADR-0028, I-01).
- 경로: `vault/` 아래 `.md` 이고, 어느 깊이에서든 `Private`·`private`·`templates` 폴더 안이 아니며, 숨김(`.` 으로 시작)·상대 경로 조각이 없다. 그래서 에닉의 기억 폴더도 이 도구로는 쓸 수 없다.
- 비밀값으로 보이는 내용이 없다.
- 공개 여부를 바꾸지 않는다:
  - 새 노트는 frontmatter 에 `draft: true` 가 있어야 한다.
  - 있는 노트는 쓰기 전후의 `draft` 판정이 같아야 한다. 공개된 글은 공개된 채로 고치고, 초안은 초안으로 고친다.
  - `draft` 판정은 Quartz 와 같다: frontmatter 의 `draft` 가 `true` 또는 문자열 `"true"`.

### 3. 커밋
- 메시지는 `blog: created|updated <파일 이름>`.
- 결과가 초안이면 CI 를 건너뛰는 표시를 붙여 블로그 빌드를 돌리지 않는다(ADR-0028 §4 와 같다). 공개된 글을 고쳤으면 붙이지 않아 블로그가 다시 배포된다.
- 쓴 노트는 곧바로 색인에 반영한다.

### 4. 하지 않는 것
- 공개 노트 삭제와 이동(이름 바꾸기)은 이번에 넣지 않는다. 필요해지면 같은 확인을 지나는 도구로 더한다.
- 소유자의 메시지에 반응을 붙이지 않는다. 에이전트가 답에서 무엇을 썼는지 알린다.

## 근거
- 공개는 되돌리기 어려운 유일한 결과다. 내용의 잘못은 git 이력으로 되돌릴 수 있다. 그래서 공개 여부만 소유자에게 남기고 나머지는 연다.
- `draft` 를 지키는 확인은 경로 확인과 독립적인 두 번째 방어선이다. ADR-0028 이 기억 노트를 두 겹으로 막은 방식을 공개 노트에서는 "공개 상태 불변"으로 바꾼다.
- 기억 쓰기와 같은 토큰·경로·비밀값 확인을 다시 써서, 새 권한이나 비밀값이 생기지 않는다.

## 결과
- I-35 가 바뀐다: 에닉은 자기 폴더 밖에서는 공개 노트만, 공개 여부를 바꾸지 않고 쓴다.
- 에닉이 소유자의 공개된 글을 고치면 바로 블로그에 반영된다. 소유자는 git 이력(볼트 저장소)으로 확인하고 되돌린다.
- Quartz 의 `ignorePatterns` 나 draft 규칙이 바뀌면 core 의 판정(`UNPUBLISHED_DIRS`, `is_draft`)도 함께 바꿔야 한다.

## 재검토 조건
- 블로그 렌더 방식이나 공개 제외 규칙이 바뀔 때.
- 소유자가 에닉에게 공개 여부까지 맡기고 싶어 할 때.
- 삭제·이동이 필요해질 때.
