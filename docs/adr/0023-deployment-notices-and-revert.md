# ADR-0023: 배포 결과 알림과 되돌리기

- 상태: 승인
- 날짜: 2026-11-22
- 관련: ADR-0008, ADR-0019, ADR-0020, ADR-0021, ADR-0024, I-18, I-24, I-28, I-34

## 배경
ADR-0020 §3 은 배포 실패 대응으로 RollingUpdate, PostSync 스모크 검사, [되돌리기] 버튼을 정했다. 소유자는 여기에 더해 다음을 원한다.

- 배포가 끝나면 성공이든 실패든 DM 으로 알린다.
- 되돌리기를 했으면 그 결과(성공, 실패)도 DM 으로 알린다.
- `main` 의 이미지 빌드가 실패해 배포가 시작되지 않은 경우도 알린다.

배포 경로의 사실은 다음과 같다(ADR-0008).

- `main` 머지 → GitHub Actions `images` 가 이미지 `sha-<커밋>` 을 빌드한다. `src/`, `agents/`, `config/` 등 이미지에 들어가는 경로가 바뀐 경우에만 빌드한다.
- Argo CD Image Updater 가 새 태그를 Argo CD Application 의 helm 파라미터에 바로 쓴다(write-back `argocd`). git 에는 기록되지 않는다.
- 차트(`deploy/helm/`) 변경은 Argo CD 가 git 리비전으로 반영한다.
- 그래서 "무엇이 배포됐고 결과가 어떤가"의 원본은 Argo CD Application 상태다(I-24).

## 검토한 대안
- **PostSync Job 이 core 에 결과를 보고(ADR-0020 §3 원안)**: 성공은 알 수 있다. 그러나 동기화가 실패하거나 새 Pod 가 뜨지 않으면 PostSync 가 실행되지 않아 실패를 보고할 주체가 없다. 보고용 API 와 Job 의 인증도 따로 필요하다.
- **core 가 Argo CD Application 을 읽어 판정**: 성공과 실패를 같은 곳에서 본다. 스모크 검사는 PostSync 훅으로 두되, 훅이 실패하면 Argo CD 동기화가 실패하므로 결과는 Application 상태에 그대로 나타난다. core 에 읽기 권한만 추가된다. → 채택.
- **되돌리기를 Argo CD 롤백(이전 태그로 되돌림)으로**: 빠르다. 그러나 git 과 승인 경로를 거치지 않고(I-18, I-19), Image Updater 가 곧 최신 태그로 다시 바꾼다. → 기각.
- **되돌리기 PR 을 항상 개발 에이전트가 만듦**: 단순하다. 그러나 LLM 실행이라 느리고 결과가 매번 같다는 보장이 없다. 장애 상황에서 쓰는 기능이라 결정적이어야 한다. → 실패한 커밋이 `main` 의 최신일 때는 core 가 직접 만들고, 그 밖의 경우만 개발 에이전트에 맡긴다.

## 결정

### 1. 배포 감시
- core 가 30초마다 `argocd` 네임스페이스의 enikk 앱(`enikk-core`, `enikk-runtime-claude`, `enikk-connector-slack`, `enikk-dev-agent`)을 읽는다. 권한은 `applications` 의 get/list 뿐이다.
- 앱의 이미지 태그나 동기화 리비전이 바뀌면 배포 한 건으로 기록한다. 배포의 커밋은 이미지 태그가 바뀌었으면 태그의 커밋, 아니면 동기화 리비전이다.
- 판정:
  - **성공**: 그 리비전의 동기화가 `Succeeded` 이고 앱이 `Healthy` 다. PostSync 스모크 검사가 있는 앱은 검사 통과까지 포함된다.
  - **실패**: 동기화가 `Failed`/`Error` 이거나, 앱이 `Degraded` 이거나, 배포를 기록한 지 10분 안에 성공 조건을 채우지 못했다.
- 같은 커밋으로 배포된 앱은 DM 한 통으로 묶는다. 묶음 안의 모든 앱이 판정되고, 60초 동안 새 앱이 더해지지 않으면 보낸다.
- 커밋에서 PR 을 찾아(GitHub `commits/{sha}/pulls`) 링크와 제목을 붙인다.
- core 가 처음 시작할 때 이미 배포되어 있던 상태는 기준으로만 기록하고 알리지 않는다. core 자신이 재시작되는 배포는 새 core 가 기록된 기준과 비교해 이어서 판정한다.

### 2. 스모크 검사
- core 차트에 Argo CD PostSync 훅 Job 을 둔다. `enikk-ops smoke core` 를 실행하며, 실패하면 Job 이 실패하고 Argo CD 동기화가 `Failed` 가 된다.
- 훅 Job 은 `smoke` 역할의 ServiceAccount 로 core 를 호출한다. 결과를 보고하는 별도 API 는 두지 않는다.

### 3. 무중단 배포
- 모든 앱 Deployment 를 RollingUpdate(`maxSurge: 1`, `maxUnavailable: 0`)로 둔다(ADR-0020 §3). 새 Pod 가 준비되지 않으면 이전 Pod 가 계속 서비스한다. 실패 DM 에 이 사실을 적는다.

### 4. 빌드 실패 알림
- core 가 감시 토큰으로 관리 대상 저장소 `main` 의 `images` 워크플로 실행을 조회한다. 실패한 실행마다 한 번 DM 을 보낸다(커밋, PR, 실행 링크). 이 경우 배포는 시작되지 않았으므로 이전 버전이 그대로 동작한다.
- 감시 토큰에 `actions: read` 를 더한다(ADR-0019).

### 5. 되돌리기
- 배포 실패 DM 과 빌드 실패 DM 에 [되돌리기] 버튼을 붙인다. 소유자만 누를 수 있다(I-01).
- 누르면 core 가 되돌리기 요청을 기록하고 되돌리는 PR 을 만든다.
  - **실패한 커밋이 `main` 의 최신이면** core 가 개발 토큰으로 직접 만든다. 그 커밋의 부모 트리를 그대로 가진 새 커밋을 `agent/revert-<짧은 SHA>` 브랜치에 만들고 PR 을 연다. LLM 을 쓰지 않는다.
  - **그 뒤에 다른 커밋이 쌓였으면** 개발 에이전트에 "그 커밋을 revert 하는 PR" 작업을 위임한다. 충돌이 나면 에이전트가 PR 대신 이유를 알린다.
- 되돌리는 PR 도 같은 Slack 승인을 거친다(I-19). 승인 요청 DM 에 "되돌리기" 임을 표시한다.
- 되돌릴 커밋이 민감 경로(ADR-0024)를 바꿨다면 revert 도 민감 경로 변경으로 표시되어 강화된 승인을 거친다.

### 6. 롤백 결과 알림
- core 는 되돌리기 요청, 되돌리는 PR, 그 머지 커밋을 연결해 기록한다.
- 그 머지 커밋의 배포가 판정되면 일반 배포 알림 대신 "롤백 성공" 또는 "롤백 실패"를 보낸다. 롤백 PR 의 이미지 빌드가 실패해도 "롤백 실패"로 알린다.
- 되돌리는 PR 을 만들지 못했거나, 소유자가 그 PR 을 반려했으면 그것도 알린다.
- 되돌리는 PR 이 머지됐는데 바뀐 경로가 이미지와 차트 어느 쪽에도 해당하지 않아 배포가 없으면, 머지 시점에 "롤백 완료(배포 없음)"로 알린다.

### 7. DB 스키마 (expand/contract)
- 마이그레이션은 바로 이전 버전 코드가 새 스키마에서 그대로 동작하도록만 한다. 열과 테이블은 먼저 추가만 하고, 지우거나 이름을 바꾸거나 제약을 강화하는 일은 그것을 쓰는 코드가 모두 배포된 다음 PR 에서 한다.
- 되돌리기는 이미지와 차트만 되돌리고 스키마는 되돌리지 않는다. 이 규칙이 그 전제다.

## 근거
- Argo CD Application 의 `status.sync`, `status.health`, `status.operationState` 와 `spec.source.helm.parameters` 는 현재 클러스터에서 확인했다(2026-11-22, `enikk-core` 의 `image.tag` 파라미터와 `operationState.phase: Succeeded`).
- PostSync 훅 Job 이 실패하면 동기화 작업이 실패로 끝나는 것은 Argo CD 의 resource hook 동작이다. 구현할 때 실제 실패를 한 번 만들어 확인한다.
- `main` 최신 커밋의 revert 는 "부모 커밋의 트리"와 같으므로 GitHub git data API(트리·커밋·ref 생성)만으로 만들 수 있다.

## 결과
- I-28 을 고쳐 core 에 `argocd` 네임스페이스 `applications` 읽기 권한을 더한다.
- I-34 를 추가한다(스키마 expand/contract).
- 이미지에 들어가지 않는 변경(문서 등)은 배포가 없으므로 배포 알림도 없다.
- 실행은 되지만 동작이 틀린 배포는 여전히 스모크 검사가 잡는 범위까지만 잡힌다(ADR-0020).

## 재검토 조건
- Argo CD 알림 기능(notifications)으로 같은 판정을 더 간단히 할 수 있게 되면.
- 앱이 늘어 커밋 단위 묶음이 맞지 않게 되면.
