# ADR-0041: 에닉은 모든 권한을 갖고, 스스로 다음 일을 이어 간다

- 상태: 승인 (1단계(민감 경로 축소)·2단계(이벤트 깨우기) 구현. 3·4단계는 아래 "이행 순서")
- 날짜: 2026-11-25
- 관련: ADR-0004, ADR-0005, ADR-0010, ADR-0014, ADR-0017, ADR-0019, ADR-0024, ADR-0029, ADR-0033, ADR-0037, ADR-0039, I-11, I-12, I-14, I-16, I-17, I-20, I-25, I-28, I-29, I-32, I-37, I-39

> 결정은 2026-11-24~25 소유자가 Slack 스레드에서 확정했다. ADR-0037 과 같이, 기존 ADR 과 불변식의 대체 표시는 **실제로 바뀌는 단계**에서 단다(아래 "바뀌는 ADR·불변식"). 1단계에서 바뀌는 것은 ADR-0024 의 민감 경로 목록(I-20 의 범위)뿐이다.

## 배경

### 문제
- **권한을 좁히는 비용**: 에이전트는 에닉 하나뿐인데, 불변식의 절반 넘게가 에닉의 권한을 좁힌다(도구 허용 목록, 스킬 `requires`, 스케줄 `pending` 승인, core 경유 push, 진단 도구 경유 조회, 넓은 민감 경로). 그 결과는 느린 개발과 우회·확인에 쓰는 토큰이었다. 좁혀서 막을 다른 에이전트가 없으므로 얻는 것이 없다.
- **수동적인 진행**: 세션은 소유자의 메시지로만 깨어난다. 소유자가 PR 을 승인해도 core 는 상태 카드만 고치고(ADR-0036) 세션에 작업을 넣지 않는다. 소유자가 "승인했다"고 알려야 다음 일이 진행된다.
- **작업마다 새 프로세스**: runtime-claude 는 작업마다 Claude CLI 를 새로 띄우고 core 의 이력으로 세션을 복원한다(`enikk_engine_claude.engine`, ADR-0014·ADR-0034). 로컬 노드에서는 반복 기동 비용이 크다.
- **에이전트 사이 통신의 부재**: ADR-0037 4e 에서 위임을 없앤 뒤 에이전트끼리 통신하는 길이 없다. 앞으로 에이전트를 늘려 도구와 권한을 나눌 계획이다.

### 소유자 판단
- 권한 관리는 시스템의 틀이 갖춰진 뒤의 일이다. 만들 때부터 좁히면 자원만 낭비한다.
- 틀이 완성된 뒤에도 에닉은 모든 권한을 갖는다. 권한은 새로 늘릴 에이전트에 도구를 나눠 주며 좁힌다.

### 제약
- 클러스터는 온프레미스 단일 노드이고 자원이 한정되어 있다(runtime-claude 한도 1536Mi, CLI 하나 약 250MB).
- 저장소는 공개다. 비밀값이 새면 되돌리기 어렵다.

## 검토한 대안
- **지금처럼 단계별로 좁힌 채 유지**: 안전하다 / 위의 비용이 계속 든다.
- **모든 제한 폐지**: 가장 빠르다 / 비밀값 유출과 되돌릴 수 없는 운영 변경을 막을 장치가 없다. 신뢰하지 않는 입력(웹, 대화 원문)에 담긴 지시에 무방비가 된다.
- **에닉은 모든 권한, 경계는 셋만 남긴다** (선택): 아래 결정.

## 결정

### 1. 에닉의 권한
- **남기는 경계 셋** (소유자 결정):
  1. 비밀값 격리: 기본 도구는 Landlock 샌드박스에서 서비스의 비밀값 없이 돈다. 비밀값은 core 가 내준다(I-02, I-07, I-30, I-37). 예외는 아래 GitHub 토큰 하나다.
  2. `main` 머지와 `production` 프롬프트 승격은 소유자 승인(I-19, I-33, I-36).
  3. 운영 변경은 GitOps 만(I-18).
- **도구**: 에닉의 정의(`agents/enikk.yaml`)는 MCP 서버·도구, 기본 도구, 플랫폼 도구를 모두 `*` 로 연다. 정의 형식과 core 의 작업 토큰이 `*` 를 받는다.
- **토큰 발급 방식은 유지한다**: core 가 작업마다 MCP 토큰을 서명하고 gateway 가 확인·거른다(ADR-0039 §2). 에닉의 토큰은 모든 도구를 허용한다. 다른 에이전트의 토큰은 그 정의의 도구만 허용한다.
- **GitHub**: core 가 작업마다 GitHub App 설치 토큰(용도 `develop`: 작업 저장소 하나, `contents`·`pull_requests`·`workflows` 쓰기, `checks`·`statuses`·`metadata` 읽기)을 발급하고, 에닉이 직접 `agent/*` 브랜치에 push 하고 PR 을 만들고 닫는다. core 의 제출 경로(`submit_pull_request`, `submissions.py`)는 없앤다. `main` 은 브랜치 보호 규칙과 `enikk/owner-approval` 상태 검사가 지킨다(I-33).
  - 이 토큰은 git 이 샌드박스 안에서 돌기 때문에 샌드박스 안에서 읽힌다. 경계 1 의 유일한 예외다. 만료 1시간, 저장소 하나, `main` 머지·운영 배포 불가라 감수한다. Claude 토큰과 core 토큰은 지금처럼 샌드박스 밖에 둔다.
- **스킬 `requires`** 를 없앤다(I-16 의 예외 삭제).
- **스케줄**: `pending` 승인(대상이 자기 자신이 아니거나 10분보다 잦은 주기)과 "예약 세션은 조회만"을 없앤다. 남는 규칙은 "스케줄의 도구는 그 에이전트 정의를 넘지 못한다"뿐이다. ADR-0039 의 S4(승인 카드)는 필요 없다.
- **클러스터 읽기**: runtime 에 읽기 전용 Kubernetes 권한(`get`·`list`·`watch`, Pod 로그)을 준다. 쓰기는 GitOps 만이다(경계 3).
- **민감 경로**는 세 경계에 해당하는 파일로 줄인다: 승인·머지, 프롬프트 승격, 비밀값과 GitHub 토큰, 샌드박스, CI 와 저장소 보호, 클러스터 권한, 불변식, 그리고 목록 자신. 에이전트 정의, ADR, 제출·스케줄·MCP 토큰·gateway 경로는 뺀다.

### 2. 에이전트 통신
- agentgateway 가 에이전트 통신의 유일한 창구다. 도구 호출(MCP)과 에이전트끼리의 호출(A2A)이 모두 지난다.
- runtime 은 여러 에이전트를 실행하는 공용 실행기다. 어떤 에이전트인지는 정의 파일이, 어느 엔진인지는 정의의 `engine` 이 정한다(I-10).
- **같은 엔진은 같은 파드**: gateway 는 A2A 요청을 대상 에이전트의 엔진 런타임으로 보낸다. 대상이 Claude 에이전트면 에닉이 돌고 있는 runtime-claude 파드가 받고, 새 파드 없이 그 파드에 대상 에이전트의 세션을 연다(자원 최적화).
- **흐름**: 에닉의 A2A 호출 → gateway → 대상 엔진의 runtime → runtime 이 core 에 하위 작업 등록(부모 작업·세션 연결) → core 가 하위 에이전트 정의의 도구만 담은 토큰 발급 → 같은 파드에서 실행 → 결과를 호출자에게 돌려줌.
- 작업·세션·임대·취소 상태의 원본은 core 다. runtime 은 core 에 등록하지 않은 세션을 만들지 않는다. gateway 는 상태를 갖지 않는다.
- 대화 맥락은 에닉만 갖는다. 하위 에이전트는 좁은 도구로 일하고 결과만 돌려준다(ADR-0037 이 없앤 긴 위임문으로 돌아가지 않는다).
- 부모 작업이 취소되면 하위 작업도 취소된다.
- 하위 작업은 일반 칸과 따로 센다. 부모가 칸을 차지한 채 기다리므로 같은 칸을 나눠 쓰면 교착이 생긴다. 상한은 메모리로 정한다(구현 때 실측).
- 구현은 두 번째 에이전트가 생길 때 한다. 이 ADR 은 방향만 정한다.

### 3. runtime 세션 유지
- runtime-claude 는 세션(스레드)마다 CLI 하나를 장수 클라이언트로 띄워 두고, 같은 세션의 다음 작업이 그대로 이어받는다.
- 일정 시간(기본 10분) 쓰이지 않은 세션, 메모리 상한을 넘기는 세션, 파드 재시작으로 끊긴 세션은 닫는다. 닫힌 세션은 지금처럼 core 의 이력으로 복원한다. 이력의 원본은 core 다(I-31 유지).
- 살려 둘 세션 수와 메모리 한도는 구현 때 실측해 정한다.

### 4. 이벤트로 세션 깨우기
- core 는 아래 이벤트가 생기면 그 PR·프롬프트 후보를 낸 세션에 작업을 넣는다.
  - PR 머지·반려·닫힘, 검사 실패
  - 배포 성공·실패
  - 프롬프트 승격·거절
- 입구는 Slack 메시지와 같은 작업 접수 경로다. 입력은 `[이벤트] PR #N 배포 성공 (sha-…)` 꼴이며 신뢰하는 core 의 글이다.
- 머지도 세션을 깨운다. 문서만 바꾼 PR 처럼 이미지가 바뀌지 않으면 배포 이벤트가 오지 않기 때문이다(2단계 구현에서 바꿈). 머지 이벤트는 "이미지가 바뀌는 변경이면 배포 결과가 따로 온다"고 알리고, 새 코드가 떠 있어야 하는 다음 단계는 배포 성공 이벤트에서 한다.
- 결과별 동작: 검사 실패는 에닉이 고쳐 같은 PR 을 갱신한다. 반려는 멈추고 이유를 묻는다. 배포 실패는 원인을 보고하며, 되돌리기는 소유자가 정한다.
- **상한은 없다**(소유자 결정). 멈추는 길은 Slack 의 [취소]다. 이벤트 작업에도 같은 [취소]가 붙고, 취소하면 그 세션의 대기·실행 중 작업과 하위 작업이 멈춘다.
- 승인 단계는 그대로다. 바뀌는 것은 승인 뒤의 흐름뿐이다.

## 근거
- 에이전트가 하나일 때 권한 분리는 막을 대상이 없다. 실제로 지킬 가치가 있는 것은 되돌릴 수 없는 것(비밀값, `main`, 운영 리소스)뿐이다.
- 토큰 발급 구조(ADR-0039 S3)는 이미 배포되어 있고, 하위 에이전트의 권한을 나누는 데 그대로 쓴다. 에닉의 토큰 범위만 넓히면 된다.
- 배포 감시(`deployments.py`)는 이미 커밋에서 PR 을 찾고, 작업 접수(`accept_event`)는 이미 스레드 문맥을 붙인다. 이벤트 깨우기는 둘을 잇는 작은 변경이다.
- agentgateway 는 MCP 와 A2A 를 모두 중계한다(확인 2026-11-24, <https://agentgateway.dev/docs/kubernetes/latest/agent/a2a/>). 버전마다 A2A 백엔드 설정 형식이 다르므로 구현 때 쓰는 버전에서 다시 확인한다.

## 결과
- 예약 세션과 이벤트 세션도 모든 권한을 갖는다. 신뢰하지 않는 입력에 담긴 지시를 막는 장치는 비밀값 격리와 소유자 승인뿐이다.
- 자동 진행에 상한이 없으므로 같은 오류가 반복되면 토큰을 계속 쓴다. 멈추는 길은 소유자의 [취소]다.
- GitHub 토큰이 샌드박스 안에서 읽힌다(만료 1시간, 저장소 하나).
- 세션을 살려 두면 메모리를 더 쓴다. 파드가 재시작되면 살아 있던 세션은 끊기고 이력에서 복원된다.

### 바뀌는 ADR·불변식 (각 단계에서 대체 표시를 단다)
- 1단계: ADR-0024 의 목록 범위(I-20). 목록만 줄이며 강화된 승인 절차는 그대로다.
- 2단계(이벤트 깨우기): I-11, I-12(스레드 세션의 입력에 core 이벤트 작업을 더함), I-29(이벤트 작업의 [취소]), ADR-0036(카드와 함께 세션 작업).
- 3단계(권한 개방): ADR-0005·I-14(정의의 `*`), ADR-0037 2a·I-16(`requires` 삭제), ADR-0037 §6b·ADR-0019·I-17·I-32(에닉에게 `develop` 토큰, core 제출 경로 삭제), ADR-0033·I-37(GitHub 토큰 예외), ADR-0039 §5·I-39(승인 규칙 삭제), ADR-0029·I-28(runtime 의 읽기 전용 Kubernetes 토큰).
- 4단계(세션 유지): ADR-0010·I-25(살아 있는 세션을 메모리에 둠), ADR-0014·ADR-0034(복원은 세션이 닫혔을 때만).
- 에이전트 통신(§2)은 두 번째 에이전트를 만들 때 별도 단계로 I-11, I-12, I-29 를 다시 고친다.

### 이행 순서 (단계마다 PR 하나)
1. 이 ADR 과 민감 경로 축소 **(이 PR)**.
2. 이벤트 깨우기 **(구현됨)**. core 의 `SessionWaker`(`enikk_core/wakeups.py`)가 PR 상태 카드(`ThreadNotes.card`)와 프롬프트 결과 알림(`PromptService._tell`)에서 그 세션에 작업을 넣는다. 깨우는 단계: 검사 실패, 머지, 머지 거부, 반려, 닫힘, 배포 성공·실패, 빌드 실패, 되돌림 성공·실패, 프롬프트 승격·거절·무효·되돌림. 검사 중·승인 대기는 소유자를 기다리므로 깨우지 않는다. 작업의 원본 이벤트 ID 는 `core-event:` 로 시작하고 이벤트마다 하나라 같은 이벤트로 두 번 깨우지 않는다. 위임 세션(4e 전)과 정의가 없어진 에이전트의 세션은 깨우지 않는다. Helm `deploy/helm/core` 의 `wakeups.enabled`(기본 true, 코드 기본 false).
3. 권한 개방: 정의의 `*`, `requires`·`pending` 삭제, `develop` 토큰과 제출 경로 삭제, 클러스터 읽기.
4. 세션 유지.

### 되돌리기
- 1단계: `config/sensitive-paths.yaml` 을 이전 목록으로 되돌린다.
- 2·4단계: Helm 값으로 끌 수 있게 만든다.
- 3단계: `agents/enikk.yaml` 을 이전 목록으로 되돌리고, `develop` 토큰 발급을 끈다.

## 재검토 조건
- 두 번째 에이전트가 생길 때(§2 구현).
- 신뢰하지 않는 입력 때문에 실제 피해가 나거나 날 뻔했을 때.
- 이벤트 자동 진행이 반복 실패로 토큰을 크게 쓴 일이 생길 때(상한 재검토).
- 메모리 부족으로 작업이 함께 끝나는 일이 반복될 때.
