# ADR-0052: 에이전트는 자기 스케줄을 만든다

- 상태: 승인 (구현)
- 날짜: 2026-11-28
- 관련: ADR-0039, ADR-0041, ADR-0045, ADR-0047, ADR-0051, I-16, I-39

> 결정은 2026-11-28 소유자가 Slack 스레드에서 확정했다.

## 배경
- 스케줄러 도구(ADR-0039)는 에닉만 가졌다. 리타와 아르카나의 정의에는 일부러 넣지 않았다(ADR-0045 §7, ADR-0051).
- 아르카나의 정기 글(동향 글, 개발 일지)처럼 전용 채널 에이전트가 자기 일을 주기적으로 하고 싶은 경우가 생겼다. 지금은 소유자가 에닉에게 따로 부탁해야 한다.
- ADR-0041 §1 이 스케줄 승인(`pending`)을 없앤 뒤, core 는 호출한 에이전트와 스케줄의 대상 에이전트를 비교하지 않는다(main `ff2ceb7`, `enikk_core.schedules`). 남은 규칙은 "스케줄의 도구는 대상 에이전트의 정의를 넘지 못한다"뿐이다(I-39).
- 그래서 도구만 열어 주면, 좁은 도구를 가진 에이전트가 대상을 `enikk` 으로 적은 스케줄을 만들어 에닉의 도구로 일을 돌릴 수 있다. 회차는 대상 에이전트의 정의 그대로 돈다(ADR-0039 S5).

## 검토한 대안
- **도구만 연다**: 가장 간단하다 / 위의 권한 상승이 생긴다. → 기각.
- **이름으로 구분한다(에닉은 무엇이든, 나머지는 자기 것만)**: 단순하다 / 코드에 에이전트 이름이 박히고, 에닉이 아닌 조정 에이전트가 생기면 다시 고쳐야 한다. → 기각.
- **에이전트 정의에 새 표시(예: `schedules: any`)를 둔다**: 명시적이다 / 표시를 잘못 주면 같은 권한 상승이 생기고, 정의의 도구와 따로 놀아 검토할 것이 늘어난다. → 기각.
- **이미 가진 권한으로 판정한다** (선택): 아래 결정.

## 결정

### 1. 누가 어느 스케줄을 다루나
호출한 에이전트 A 는 대상 에이전트 B 의 스케줄을 만들고, 고치고, 멈추고, 지우고, 지금 돌리고, 볼 수 있다. 다음 중 하나일 때만이다.
- B 가 A 자신이다(옛 이름 포함).
- B 가 A 의 `delegates` 에 있다. A 는 이미 위임(ADR-0047)으로 B 에게 일을 시킬 수 있으므로 새 권한이 아니다.
- B 의 도구가 모두 A 의 도구 안에 있다(`tools_beyond(B, A)` 가 비었다). A 가 직접 할 수 있는 일보다 넓어지지 않는다.

그 밖은 거부한다(HTTP 403). 바꾸기(`update_schedule`)는 원래 스케줄의 대상과 새 대상 모두에 이 규칙을 적용한다. 목록(`list_schedules`)에는 다룰 수 있는 스케줄만 보인다. 대상 에이전트의 정의가 없어진 스케줄은 돌 수 없으므로 누구나 다룰 수 있다.

판정은 도메인 함수 `enikk_core_domain.schedules.may_manage` 하나가 하고, `ScheduleService` 가 요청마다 부른다.

### 2. 도구를 주는 에이전트
- 리타와 아르카나의 정의에 스케줄러 도구 전부(조회, 변경, `run_now`)를 준다.
- 이 정의에서 둘은 자기 자신만 다룬다. 에닉은 위임 대상과 도구 없는 `summarizer` 를 포함해 모두를 다룬다. core 테스트(`test_catalog`)가 실제 정의로 이것을 확인한다.

### 3. 새 에이전트
- 에이전트를 새로 만들 때는 스케줄러 도구를 줄지 소유자에게 묻는다(소유자 결정). 주면 1 의 규칙에 따라 자기 스케줄만 다룬다.

## 근거
- 판정이 정의의 도구와 위임 목록에서만 나오므로, 스케줄로 얻는 권한은 그 에이전트가 이미 가진 권한을 넘지 못한다. 새 표시나 이름 목록을 관리할 필요가 없다.
- 에닉은 지금처럼 모든 스케줄을 다룬다. 아르카나의 `vault-private` 처럼 에닉에게 없는 도구를 가진 에이전트도 위임 대상이라 다룰 수 있다.

## 결과
- I-39 에 "에이전트는 자기, 위임 대상, 도구가 자기 안에 드는 에이전트의 스케줄만 다룬다"를 더한다.
- ADR-0045 §7(리타)과 ADR-0051(아르카나)의 "스케줄러 없음"은 이 ADR 로 대체된다.
- 리타의 스케줄은 이미지 생성 예산(ADR-0046)을 대화와 함께 쓴다. Unity 도구를 쓰는 회차는 PC 가 꺼져 있으면 실패한다.
- 스케줄 이름은 에이전트 사이에 하나의 공간이다. 다른 에이전트가 이미 쓴 이름으로 만들면 409 로 거부되어, 그런 이름이 있다는 것만은 알 수 있다.
- 출력 `thread` 는 스케줄을 만든 스레드에 올라간다. 에이전트 채널에서 그 캐릭터의 이름으로 보이는지는 배포 뒤 확인한다(ADR-0045 §3 에 따르면 채널이 정한다).
- 리타·아르카나의 프롬프트에 스케줄 사용 원칙을 넣는 것은 정의가 머지된 뒤 프롬프트 후보로 한다.

## 재검토 조건
- 조정 역할의 에이전트가 늘어 위임 목록과 도구 포함 관계로 표현하기 어려워질 때.
- 스케줄 이름 공간을 에이전트마다 나눠야 할 때.
