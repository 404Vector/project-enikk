# 불변식

- 상태: 작성 중
- 최종 갱신: 2026-11-22

어떤 기능 추가나 리팩터링에서도 깨지면 안 되는 조건. 깨야 한다면 먼저 근거 ADR 을 대체하는 새 ADR 을 만든다.
`잠정` 표시가 붙은 항목은 근거 ADR 이 아직 `제안` 상태라는 뜻이다.

| 번호 | 불변식 | 근거 |
|---|---|---|
| I-01 | **단일 사용자**: Slack 봇은 소유자 본인의 Slack 사용자 ID 에서 온 요청만 처리하고, 그 외 요청은 무시한다. | ADR-0002 |
| I-02 | Claude 구독 토큰은 Claude 엔진 프로세스의 환경에만 주입한다. 게이트웨이, 다른 앱, 로그, 트레이스에 노출하지 않는다. 단, enikk-core 는 이 토큰을 전달하기 위해서만 보관하며 사용하거나 기록하지 않는다. | ADR-0002, ADR-0013 |
| I-03 | Claude 모델 호출은 Claude Code / Claude Agent SDK 경로로만 하고, Anthropic API 로 직접 보낸다(게이트웨이 경유 없음). | ADR-0002, ADR-0004 |
| I-04 | Claude 인증 방식(구독 토큰 ↔ API 키)은 코드 변경 없이 설정으로 전환할 수 있어야 한다. | ADR-0002 |
| I-05 | 엔진은 MCP 도구에 agentgateway 를 통해서만 접근한다. 엔진은 개별 MCP 서버 주소를 모른다. | ADR-0004 |
| I-06 | 관측 데이터는 OpenTelemetry 로 계측한다. Langfuse SDK 에 직접 의존하는 코드는 관측 통합 패키지 안에만 있다. | ADR-0001 |
| I-07 | 비밀값(토큰, API 키)은 git, 명령 인자, 로그, 트레이스에 남기지 않는다. 클러스터에서는 core 전용 Secret 에만 있고, 다른 서비스는 core 의 비밀값 API 로만 받는다. | ADR-0001, ADR-0002, ADR-0013 |
| I-08 | 도메인 코어는 특정 모델 공급사(Anthropic, Google)의 SDK 나 타입을 import 하지 않는다. | ADR-0003 |
| I-09 | MCP 서버가 쓰는 외부 자격증명은 해당 MCP 서버만 가진다. 엔진과 게이트웨이는 갖지 않는다. | ADR-0004 |
| I-10 | 어떤 엔진으로 실행할지는 에이전트 정의 파일에서만 정한다. 코드에 엔진 선택 분기를 두지 않는다. | ADR-0003 |
| I-11 | Slack 스레드 하나는 에이전트 정의 하나에 묶이며, 대화 이력은 그 엔진의 세션으로 관리한다. | ADR-0003 |
| I-12 | 엔진이 다른 에이전트 사이의 위임은 명시적인 입력과 출력만 주고받는다. 대화 이력을 엔진 간에 옮기지 않는다. | ADR-0003 |
| I-13 | 프롬프트 본문은 git 저장소에 존재하지 않는다. 원본은 Langfuse 이며, 가져올 수 없으면 임의의 기본 프롬프트로 대체하지 않고 실행을 거부한다. | ADR-0006 |
| I-14 | 엔진 내장 도구(셸, 파일, 웹 검색, 코드 실행 등)는 기본 차단이며, 에이전트 정의에 명시된 것만 허용한다. | ADR-0005 |
| I-15 | 에이전트 정의는 Slack 등 특정 인터페이스를 모른다. 인터페이스와 에이전트의 연결 규칙은 인터페이스 쪽 설정에 둔다. | ADR-0005 |
| I-16 | Langfuse 에서 바꿀 수 있는 것은 프롬프트 본문, 모델 ID, 생성 파라미터뿐이다. 권한(도구, 위임 대상)은 git 의 정의 파일에서만 바뀐다. 실행 시 엔진과 모델 ID 의 호환성을 검증한다. | ADR-0005 |
| I-17 | Slack 에 응답하는 실행용 에이전트는 git 쓰기 권한과 클러스터 쓰기 권한을 갖지 않는다. 코드·정의 변경은 격리된 개발 에이전트만 만든다. | ADR-0007 |
| I-18 | 운영 배포는 GitOps 컨트롤러만 수행한다. 에이전트와 사람 모두 운영 리소스를 `helm`/`kubectl` 로 직접 바꾸지 않는다 (컨트롤러 최초 설치 등 부트스트랩 제외). | ADR-0008 |
| I-19 | `production` 프롬프트 승격과 `main` 머지는 소유자 승인이 필요하다. 에이전트는 자기 변경을 승인하거나 머지할 수 없다. | ADR-0007 |
| I-20 | 에이전트가 만든 변경은 보호 경로(불변식, ADR, CI 설정, 개발 에이전트 자신의 정의, 승인 절차)를 수정할 수 없다. CI 에서 검사한다. | ADR-0007 |
| I-21 | Secret 은 사람만 만든다. 에이전트는 필요한 Secret 을 안내만 한다. | ADR-0007 |
| I-22 | 커넥터(Slack 등)는 에이전트를 실행하지 않고 enikk-core 와만 통신한다. 런타임은 core 가 배정한 작업만 실행한다. | ADR-0010 (ADR-0009 대체) |
| I-23 | enikk-core 는 LLM 호출과 MCP 호출 경로에 있지 않다. 이 호출은 런타임이 직접 한다. | ADR-0010 |
| I-24 | enikk-core 는 설정의 원본을 갖지 않는다. 에이전트 정의는 git, 프롬프트는 Langfuse, 배포 상태는 GitOps 가 원본이다. | ADR-0010 |
| I-25 | 엔진 런타임은 상태를 갖지 않는다. 작업·세션 상태는 enikk-core 와 그 저장소에만 있다. | ADR-0010 |
| I-26 | 데이터베이스에는 enikk-core 만 접근하며, core 안에서도 레포지토리·Unit of Work 포트를 통해서만 접근한다. 스키마 변경은 마이그레이션으로만 한다. | ADR-0011 |
| I-27 | 서비스 경계를 넘는 데이터(API, 큐 메시지, 이벤트)는 공용 계약 패키지의 pydantic 모델로만 표현한다. 원시 JSON·`dict` 로 주고받지 않는다. 유일한 예외는 엔진 대화 이력 항목이며, JSON 값으로만 검증하고 core 는 해석하지 않는다. | ADR-0011, ADR-0014 |
| I-28 | core API 의 모든 요청은 audience=`enikk-core` ServiceAccount 토큰으로 인증되고, API 별로 선언된 역할만 허용된다. 인증 없는 엔드포인트는 상태 확인(health)뿐이다. core 를 제외한 자체 서비스 Pod 는 Kubernetes API 토큰을 받지 않으며, core 는 TokenReview 권한만 갖는다. | ADR-0011 |
| I-29 | 한 세션(스레드)에서 동시에 실행되는 작업은 최대 1개다. 같은 세션의 작업은 접수 순서대로 배정된다. | ADR-0012 |
| I-30 | 비밀값의 원본은 소유자 PC 의 파일이며 `enikk-ops secret` 으로만 관리한다. core 는 역할 바인딩에 허용된 비밀값만 그 호출자에게 내주고, 서비스는 받은 값을 메모리에만 둔다. | ADR-0013 |
| I-31 | 엔진 대화 이력은 core 의 저장소에만 영속한다. 런타임은 활성 임대를 가진 작업의 세션 이력에만 접근할 수 있다. | ADR-0014 |
