# 불변식

- 상태: 작성 중
- 최종 갱신: 2026-11-24

어떤 기능 추가나 리팩터링에서도 깨지면 안 되는 조건. 깨야 한다면 먼저 근거 ADR 을 대체하는 새 ADR 을 만든다.
`잠정` 표시가 붙은 항목은 근거 ADR 이 아직 `제안` 상태라는 뜻이다.
"에이전트"는 `agents/*.yaml` 하나로 정의된 실행 주체다. 지금은 에닉(`enikk`)과 대화 요약용 도구 없는 정의(`summarizer`, 스케줄러로 옮길 때까지)가 있다. 아래의 "역할"은 에이전트 정의를 뜻하며 옛 표현이다(ADR-0037 5b, ADR-0031 대체).

| 번호 | 불변식 | 근거 |
|---|---|---|
| I-01 | **단일 사용자**: Slack 봇은 소유자 본인의 Slack 사용자 ID 에서 온 요청만 처리하고, 그 외 요청은 무시한다. 예외로, 소유자가 아닌 사람이 버튼(#release 의 [되돌리기], 승인 채널의 [승인하고 머지]·[반려]·[승격] 등)을 누르면 아무것도 실행하지 않고 그 사람에게만 보이는 정해진 거절 안내를 보낸다. | ADR-0002, ADR-0026, ADR-0036 |
| I-02 | Claude 구독 토큰은 Claude 엔진 프로세스의 환경에만 주입한다. 게이트웨이, 다른 앱, 로그, 트레이스에 노출하지 않는다. 단, enikk-core 는 이 토큰을 전달하기 위해서만 보관하며 사용하거나 기록하지 않는다. | ADR-0002, ADR-0013 |
| I-03 | Claude 모델 호출은 Claude Code / Claude Agent SDK 경로로만 하고, Anthropic API 로 직접 보낸다(게이트웨이 경유 없음). | ADR-0002, ADR-0004 |
| I-04 | Claude 인증 방식(구독 토큰 ↔ API 키)은 코드 변경 없이 설정으로 전환할 수 있어야 한다. | ADR-0002 |
| I-05 | 엔진은 MCP 도구에 agentgateway 를 통해서만 접근한다. 엔진은 개별 MCP 서버 주소를 모른다. MCP 요청은 core 가 작업마다 서명한 토큰을 지니며, gateway 는 그 토큰을 확인하고 토큰이 허용한 도구만 보이고 허용한다. 토큰은 CLI 인자와 도구의 셸에 나타나지 않는다. 런타임이 직접 제공하고 core API 만 호출하는 플랫폼 도구(위임)는 MCP 도구가 아니다. | ADR-0004, ADR-0022, ADR-0039 |
| I-06 | 관측 데이터는 OpenTelemetry 로 계측한다. Langfuse SDK 에 직접 의존하는 코드는 관측 통합 패키지 안에만 있다. | ADR-0001 |
| I-07 | 비밀값(토큰, API 키)은 git, 명령 인자, 로그, 트레이스에 남기지 않는다. 클러스터에서는 core 전용 Secret 에만 있고, 다른 서비스는 core 의 비밀값 API 로만 받는다. | ADR-0001, ADR-0002, ADR-0013 |
| I-08 | 도메인 코어는 특정 모델 공급사(Anthropic, Google)의 SDK 나 타입을 import 하지 않는다. | ADR-0003 |
| I-09 | MCP 서버가 쓰는 외부 자격증명은 해당 MCP 서버만 가진다. 엔진과 게이트웨이는 갖지 않는다. | ADR-0004 |
| I-10 | 어떤 엔진으로 실행할지는 에이전트 정의 파일(`agents/*.yaml`)에서만 정한다. 코드에 엔진 선택 분기를 두지 않는다. 옛 이름은 정의의 `aliases` 로만 이어 쓴다. | ADR-0003, ADR-0037 |
| I-11 | Slack 스레드 하나는 에이전트 정의 하나(옛 이름으로 기록된 스레드는 그 이름을 별칭으로 가진 정의)에 묶이며, 대화 이력은 그 엔진의 세션으로 관리한다. 스레드의 사용자 메시지는 그 역할만 받는다. 다른 역할에 위임하는 길은 없다(ADR-0037 4e). 그 전에 위임된 하위 세션은 그 스레드에 결과를 게시만 한다. | ADR-0003, ADR-0022, ADR-0037 |
| I-12 | 대화 이력을 엔진이나 세션 사이에 옮기지 않는다. 단, 같은 스레드에 이미 게시된 다른 세션(core 의 알림, 4e 전의 위임 세션)의 글은 그 스레드 역할의 다음 입력 앞에 붙인다. 역할 사이의 위임은 ADR-0037 4e 에서 없앴다. | ADR-0003, ADR-0027, ADR-0037 |
| I-13 | 프롬프트 본문은 git 저장소에 존재하지 않는다. 원본은 Langfuse 이며, 가져올 수 없으면 임의의 기본 프롬프트로 대체하지 않고 실행을 거부한다. | ADR-0006 |
| I-14 | 엔진 내장 도구(셸, 파일, 웹 검색, 코드 실행 등)는 기본 차단이며, 에이전트 정의에 명시된 것만 허용한다. | ADR-0005, ADR-0037 |
| I-15 | 에이전트 정의는 Slack 등 특정 인터페이스를 모른다. 인터페이스와 에이전트의 연결 규칙은 인터페이스 쪽 설정에 둔다. | ADR-0005 |
| I-16 | Langfuse 에서 바꿀 수 있는 것은 프롬프트 본문, 모델 ID, 생성 파라미터뿐이다. 권한(도구)은 git 의 에이전트 정의 파일에서만 바뀐다. 예외로 스킬 프롬프트(`skill-*`)의 config 에는 그 스킬이 쓰는 core 경유 동작(`requires`: `repo.push`, `pr.write`, `prompt.propose`)을 선언하며, 이 값은 소유자의 승격으로만 `production` 이 되고 넓히는 변경은 승격 카드에 경고가 뜬다. 실행 시 엔진과 모델 ID 의 호환성을 검증한다. | ADR-0005, ADR-0037 |
| I-17 | Slack 에 응답하는 실행용 역할은 git 자격 증명과 클러스터 쓰기 권한을 갖지 않는다. 코드·정의 변경은 `pull-requests` 를 받은 공용 역할이 스레드 worktree 의 커밋을 core 에 넘겨 core 가 검사·push 한다(그 스레드의 `agent/<세션>` 브랜치만, `main`·강제 push 없음). 격리된 개발 역할(developer)은 ADR-0037 4e 에서 없앴다. | ADR-0007, ADR-0037 |
| I-18 | 운영 배포는 GitOps 컨트롤러만 수행한다. 에닉(어느 역할이든)과 사람 모두 운영 리소스를 `helm`/`kubectl` 로 직접 바꾸지 않는다 (컨트롤러 최초 설치 등 부트스트랩 제외). | ADR-0008 |
| I-19 | `production` 프롬프트 승격과 `main` 머지는 소유자 승인이 필요하다. 에닉은 어느 역할로도 자기 변경을 승인하거나 머지할 수 없다. `main` 으로 가는 모든 PR 의 승인은 소유자가 Slack 에서 하며(I-33), 브랜치 보호 규칙에 예외를 두지 않는다. | ADR-0007, ADR-0020 |
| I-20 | 민감 경로(불변식, ADR, CI 설정, 역할 정의, 승인 절차, 권한 설정 등, 목록은 `config/sensitive-paths.yaml`)를 바꾸는 PR 은 강화된 승인(경고 표시, 본문 diff, 확인 창)을 거쳐야 머지된다. 판정은 실행 중인 core 의 목록으로 한다. | ADR-0007, ADR-0024 |
| I-21 | Secret 은 사람만 만든다. 에닉은 필요한 Secret 을 안내만 한다. | ADR-0007 |
| I-22 | 커넥터(Slack 등)는 역할을 실행하지 않고 enikk-core 와만 통신한다. 런타임은 core 가 배정한 작업만 실행한다. | ADR-0010 (ADR-0009 대체) |
| I-23 | enikk-core 는 LLM 호출과 MCP 호출 경로에 있지 않다. 이 호출은 런타임이 직접 한다. | ADR-0010 |
| I-24 | enikk-core 는 설정의 원본을 갖지 않는다. 역할 정의는 git, 프롬프트는 Langfuse, 배포 상태는 GitOps 가 원본이다. 예외로 스케줄은 설정이 아니라 소유자의 데이터로 보고 core DB 가 원본이다. 스케줄이 할 수 있는 일의 상한은 여전히 git 의 에이전트 정의다(I-39). | ADR-0010, ADR-0039 |
| I-25 | 엔진 런타임은 상태를 갖지 않는다. 작업·세션 상태는 enikk-core 와 그 저장소에만 있다. 예외로 런타임의 공유 볼륨에는 다시 만들 수 있는 것(저장소 사본, 스냅샷, 스레드별 worktree·임시 자료)만 두며, 비밀값과 자격 증명은 두지 않는다. | ADR-0010, ADR-0037 |
| I-26 | 데이터베이스에는 enikk-core 만 접근하며, core 안에서도 레포지토리·Unit of Work 포트를 통해서만 접근한다. 스키마 변경은 마이그레이션으로만 한다. | ADR-0011 |
| I-27 | 서비스 경계를 넘는 데이터(API, 큐 메시지, 이벤트)는 공용 계약 패키지의 pydantic 모델로만 표현한다. 원시 JSON·`dict` 로 주고받지 않는다. 유일한 예외는 엔진 대화 이력 항목이며, JSON 값으로만 검증하고 core 는 해석하지 않는다. | ADR-0011, ADR-0014 |
| I-28 | core API 의 모든 요청은 audience=`enikk-core` ServiceAccount 토큰으로 인증되고, API 별로 선언된 역할만 허용된다. 인증 없는 엔드포인트는 상태 확인(health)과 MCP 토큰의 공개 키(`/v1/mcp/jwks`, ADR-0039 S3)뿐이다. core 를 제외한 자체 서비스 Pod 는 Kubernetes API 토큰을 받지 않으며, core 는 TokenReview 권한, `argocd` 네임스페이스의 Application 읽기 권한, `enikk` 의 Pod 와 Pod 로그 읽기 권한만 갖는다(`enikk-dev` 의 Job·Pod 권한은 ADR-0037 4e 에서 없앴다). | ADR-0011, ADR-0021, ADR-0023, ADR-0029, ADR-0037, ADR-0039 |
| I-29 | 한 세션(스레드)에서 동시에 실행되는 작업은 최대 1개다. 같은 세션의 작업은 접수 순서대로 배정된다. 서로 다른 세션은 runtime 의 칸 수만큼 동시에 돈다. 소유자만 스레드의 [취소] 버튼으로 그 세션의 대기·실행 중 작업을 취소할 수 있고, 취소된 작업의 heartbeat·결과는 거부된다. | ADR-0012, ADR-0037 |
| I-30 | 비밀값의 원본은 소유자 PC 의 파일이며 `enikk-ops secret` 으로만 관리한다. core 는 역할 바인딩에 허용된 비밀값만 그 호출자에게 내주고, 서비스는 받은 값을 메모리에만 둔다. | ADR-0013 |
| I-31 | 엔진 대화 이력은 core 의 저장소에만 영속한다. 런타임은 활성 임대를 가진 작업의 세션 이력에만 접근할 수 있다. | ADR-0014 |
| I-32 | GitHub App 개인 키와 설치 토큰은 core 밖으로 나가지 않는다(개발 역할에 주던 토큰은 ADR-0037 4e 에서 없앴다). 공용 런타임의 세션은 GitHub 토큰을 받지 않는다. 그 커밋은 core 가 자기 clone 에서 `submit` 토큰으로 push 하며, core 는 런타임의 공유 볼륨에서 git 을 실행하지 않는다. | ADR-0019, ADR-0024, ADR-0037 |
| I-33 | `main` 으로 가는 PR 은 필수 상태 검사 `enikk/owner-approval`(출처: App `enikk-deployer`)를 통과해야 머지된다. core 는 소유자가 Slack 에서 승인한 바로 그 커밋에만 이 상태를 기록한다. | ADR-0020 |
| I-34 | DB 마이그레이션은 바로 이전 버전 코드가 새 스키마에서 동작하도록만 한다(expand/contract). 열·테이블의 삭제, 이름 변경, 제약 강화는 그것을 쓰는 코드가 모두 배포된 뒤 별도 PR 에서 한다. | ADR-0023 |
| I-35 | 에닉의 기억은 소유자의 Obsidian 볼트 저장소가 원본이며 core 는 색인만 갖는다. 기억은 참고일 뿐 규칙·권한을 바꾸지 못한다. 비밀값은 기억하지 않는다. 쓰기는 소유자가 Slack 에서 시작한 작업에서만 하고(예외: core 가 쓰는 날짜별 대화 요약, I-38), 에닉의 폴더(`vault/Private/enikk/`) 밖은 고치지 않으며, 에닉의 노트는 공개되지 않는 위치와 `draft: true` 를 가진다. | ADR-0028, ADR-0035 |
| I-36 | Langfuse 의 프롬프트 버전과 label 은 core 만 바꾼다. 역할은 core 를 거쳐 `candidate` label 만 단 후보 버전을 만들 수 있고(역할의 프롬프트와 스킬 `skill-*`), `production` label 은 소유자가 Slack 에서 누른 승격·되돌리기로만 옮겨진다. 승격은 요청 때의 `production` 버전이 그대로일 때만 한다. 스킬의 `requires` 를 넓히는 후보는 승격 요청에 그 사실을 경고로 보인다. | ADR-0032, ADR-0037 |
| I-37 | 모델이 쓰는 기본 도구(명령, 파일, 웹)는 서비스의 비밀값(Claude 토큰, core 토큰, Langfuse 키 등)을 읽을 수 없는 곳에서만 실행한다. 그런 격리를 만들 수 없으면 공용 역할은 기본 도구 없이 실행한다. 웹에서 가져온 내용은 신뢰하지 않는 입력이며 규칙·권한을 바꾸지 못한다. | ADR-0033 |

| I-39 | 스케줄의 도구는 그 에이전트 정의를 넘지 못하며, 소유자의 승인으로도 넓힐 수 없다. 입력과 출력은 코드에 등록된 종류만 쓴다. 스케줄은 소유자가 Slack 에서 시작한 세션만 바꾸고, 예약으로 열린 세션은 조회만 한다. 호출한 에이전트 자신이 대상이 아니거나 주기가 10분보다 잦은 스케줄은 `pending` 으로 남고, 소유자 승인 없이 돌지 않는다. core 는 요청마다 호출한 작업의 임대를 확인하고, 에이전트와 세션을 그 작업에서 정한다. | ADR-0039 |
