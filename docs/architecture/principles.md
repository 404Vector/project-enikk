# 설계 원칙

- 상태: 초안
- 최종 갱신: 2026-11-21

코드 구조와 구현 판단의 근거. 원칙끼리 충돌할 때는 번호가 작은 것을 우선한다.

| 번호 | 원칙 | 구체적 규칙 |
|---|---|---|
| P-01 | **의존성은 안쪽으로만** | 인터페이스(앱) → 통합(어댑터) → 도메인 코어 → 기반(kernel). 하위 계층은 상위 계층을 import 하지 않는다. `import-linter` 로 기계적으로 강제한다. |
| P-02 | **포트 & 어댑터** | 외부 시스템(LLM, Slack, MCP, Langfuse, Kubernetes, 프로세스 실행)은 도메인이 정의한 포트(Protocol) 뒤에 둔다. 구현체 교체가 도메인 코드 변경을 일으키면 안 된다. |
| P-03 | **단일 조립 지점** | 객체 생성과 연결은 각 앱의 조립 지점(Composition Root)에서만 한다. 전역 싱글턴, 모듈 레벨 인스턴스를 두지 않는다. 의존성은 생성자 주입. |
| P-04 | **불변 값 객체** | 도메인 데이터는 불변 pydantic 모델(`frozen=True`, `strict=True`, `extra="forbid"`)로 만들고 생성 시점에 검증한다. 잘못된 상태의 객체가 존재할 수 없게 한다. |
| P-05 | **타입 있는 계층형 설정** | 우선순위: 코드 기본값 < 설정 파일 < 환경변수 < CLI 옵션. 설정 스키마는 앱에 두고, 라이브러리에는 도메인 객체로 변환해 넘긴다. |
| P-06 | **명시적 에러 계층** | 모든 예외는 프로젝트 공통 루트 예외의 하위 클래스다. 예외를 사용자 메시지 / 종료 코드 / Slack 응답으로 바꾸는 것은 인터페이스 계층만 한다. |
| P-07 | **추가로 확장, 수정으로 확장하지 않음** | 새 기능 = 새 유스케이스 + 새 등록. 새 모델 = 새 엔진 구현. 새 도구 = 새 MCP 서버. 기존 코드 수정을 최소화한다. |
| P-08 | **테스트 가능성 우선** | 모든 외부 호출은 포트를 거치므로 가짜 구현으로 대체해 외부 시스템 없이 테스트한다. 테스트는 각 패키지 안에 둔다. |
| P-09 | **부작용의 가시성** | 상태를 바꾸는 동작은 로그로 남고 dry-run 이 가능해야 한다. 비밀값은 인자(argv), 로그, 트레이스에 남기지 않는다. |
| P-10 | **배포 자산과 코드의 분리** | Dockerfile, Helm 차트는 `deploy/` 에 둔다. Python 코드는 "어떤 값으로 배포할지"만 결정하고 리소스 정의를 중복 생성하지 않는다. |
| P-11 | **기록은 docs 에** | 설계 결정, 원칙, 불변식은 `docs/` 에만 적는다. 코드 주석은 "무엇을 하는지"까지만 설명하고 "왜 이렇게 설계했는지"는 문서를 참조한다. |
| P-12 | **엄격한 정적 검사** | lint, format, 타입 검사(strict), 계층 검사, 테스트가 모두 통과해야 변경을 받아들인다. |
| P-13 | **경계에서 파싱, 내부는 객체만** | 외부 입력(HTTP, 큐, 파일, 환경변수)은 경계에서 즉시 pydantic 모델로 파싱한다. 내부 코드는 원시 JSON 문자열, `dict[str, Any]`, 원시 SQL 을 다루지 않는다. 사람이든 에이전트든 실수할 수 있는 방식은 정적 검사로 막는다. |
| P-14 | **영속성은 레포지토리 뒤에** | 저장소 접근은 도메인이 정의한 레포지토리·Unit of Work 포트를 통해서만 한다. ORM 모델은 영속성 어댑터 밖으로 나가지 않는다. |
